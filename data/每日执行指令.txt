1. 开始同步最新开奖数据
────────────────────────────────────────────────────────────────────────
   → 抓取脚本：backend/data_acquisition/fetch_kl8_history.py
   → 双源：17500 与中福彩 CWL，失败自动切换；增量去重

   → 抓取失败会以非零码退出，夜间流水线判定 FAILED；禁止带旧数据继续跑预测

2. 点位与三高录入
────────────────────────────────────────────────────────────────────────

   【方式 A：自动 Excel 解析（推荐，零手动）】
   把最新点位图 Excel（含「快乐8点位图」Sheet）放入：
       validation/file/
   运行「一键全流程」时会自动解析入库；也可单独执行：
       scripts/auto_import_daily_excel.bat
   解析器：scripts/import_daily_excel.py / scripts/import_daily_excel.ps1（依赖 WPS 表格 COM）
   当天没有新 Excel 时平稳降级：沿用上一期留档点位继续跑，并在控制台明确提示

   【方式 B：手动录入（备用模式）】
   【今日点位】20 码（必须恰好 20 个，1-80，不重复）：
   （在此粘贴）

   【快8上期开奖号码重复高概率的号码】：
   （在此粘贴）

   【快8上期开奖号码的边码高概率要开出的号码】（左 4 码 ｜ 右 4 码）：
   （在此粘贴）

   【快8下期重点关注指标冷号高概率的号码】：
   （在此粘贴）

   → 落库位置（缺一不可，光贴文字不落库等于没录）：
      · 点位 → storage/raw/daily_points.txt
        行格式：date:YYYY-MM-DD,period:NNNNNN,points:NN NN ...（按期号降序，最新在最上面）
      · 三高 → storage/points/tri_high_points.json
        结构：{"records":[{period/date/repeat_high/edge_high_left/edge_high_right/cold_high}]}
   → 录入入口：Web「运维 → 点位录入 / 三高录入」，或命令行
      python scripts/input_daily_points.py --points "01 02 03 ... 20 个号码"
   → 为什么必须落库：热码 RATIO 加权、Excel 点位底色、点位+遗漏、未开点位反弹、
      三高×点位共振、点位 012 偏态压缩器，全部从这两个文件读
   → 落库后自动联动：热码生成 → 热码同步 → Excel 上色 → 空间点位 → 未开反弹 → 16 期简报

   → 昨天没有产出当期产物的模块，如实写「无当期产物」，绝不允许用历史号码或模板号码顶替

4. 开始执行所有的预测，所有模块详细输出，包括汇总、Excel 与微信分桶原文
────────────────────────────────────────────────────────────────────────
   → 推荐执行：python scripts/run_daily_complete.py
   → 深度 / 排错：python -m backend.pipeline.run_full_pipeline
   → 必须产出：
      · 工业级日报：storage/reports/daily_analysis_report_YYYYMMDD.md
      · 微信分桶原文：storage/reports/wechat_publish_<目标期>.txt
      · 各模块输出：storage/outputs/<module>/
      · Excel 类：热码统计 xlsx、跟随+点位+开奖数据.xlsx、16 期窗口 xlsx、回测表
   → 控制台按「〇 数据基准 → 一 昨日复盘 → 二 全模块逐项 → 三 微信分桶 → 四 总账单 → 五 速查块」展开
   → 严禁省略号、严禁只报几个模块就说"其余见文件"


────────────────────────────────────────────────────────────────────────
5. 发现代码和逻辑有问题请先指出来纠正，并正确解决，功能正常，并正确执行
────────────────────────────────────────────────────────────────────────
   → 先体检再开跑，发现缺陷先指出问题、说清影响面、再修，修完重跑验证
   → 重点排查：
      · 有没有用历史号码/模板号码顶替当期缺口（伪造数据，最高优先级）
      · 点位与三高是否按标准格式落库、目标期号有没有串期
      · 注册表里 status=retired 的模块是否还在参与出号或记账
      · 残留 *.excel_lock 锁文件、Excel 被占用导致写失败
      · 路径是否统一走 backend/utils/paths.py，有没有硬编码指向已迁移的旧目录
      · 夜间状态是否真实（SUCCESS/FAILED）、运行锁是否正常释放
   → 修完必须物理验证：产物文件真实存在、>0 字节、字段齐全，不许只口头说"已修复"

────────────────────────────────────────────────────────────────────────
