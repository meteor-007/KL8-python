  快乐8 每日全流程执行指令 · 唯一权威版 (v3.1  ·  2026-11-26)
  ──────────────────────────────────────────────────────────────────────
  本文件 = 每日操作的唯一权威口径。
  历史上曾并存四套指令（每日指令.txt / 每日执行指令.txt /
  docs/全流程执行指令_v2.md / docs/daily_prompts/），入口互相矛盾、
  数据源顺序过期、还写死着某一期。本版把它们合并，其余降为附录。

  v3.1 变更（2026-11-26）：
    · 点位/三高 Excel 导入已并入全流程「任务1.15」，不再需要先手动跑 bat；
    · 导入失败/文件过期不再静默，改为明确退出码 + 研报缺口清单点名；
    · 期号改成按「点位块首行」锚定，删掉"超前就掰回"的猜测逻辑。

【每天只做一件事】
   把当天的点位图 Excel（含「快乐8点位图」工作表，通常文件名 2026xxx(2).xls）
   丢进  validation\file\  ，然后跑一次全流程。点位 20 码 + 三高（重复高/边码/冷号）
   都会由「任务1.15」自动解析入库，不用再单独录。

   当天确实没有新图时也照跑：点位/三高缺席会被研报第五章点名，不会拿旧图冒充当日。


────────────────────────────────────────────────────────────────────────
  〇、唯一入口
────────────────────────────────────────────────────────────────────────
  一键执行（在 data/ 目录下）：

      python -m backend.pipeline.run_full_pipeline

  它跑完这些（顺序固定，2026-11-26 起多了 1.15）：
      任务0 环境预检 → 任务0.0 数据校验自愈 → 任务1.1 抓开奖
      → **任务1.15 点位/三高 Excel 导入（新增）** → 任务1.2 热码 → 1.3~1.5 Excel 同步
      → 任务2 昨日复盘 → 3.x 各模块推演 → 收割入前瞻账 → 任务4 标准研报+日报
      → 任务5 完整性校验 → 任务6 清缓存 → 任务7 提交并推送

  这是全流程的唯一入口。`scripts/run_daily_complete.py` 已废弃，
  不要再使用（它的报告引擎与标准研报重复，且曾把日报写错位置）。
  它唯一的独有能力「盖尔·霍华德旋转矩阵缩水方案」已下沉为独立子系统：

      python -m backend.modules.wheel_matrix.cli

  （注意：该子系统读取的是它自己的历史数据文件，目前只到 2026100 期，
    落后主系统约 200 期。用它出的方案时请留意数据时效。）

  ⚠️ 什么时候跑决定目标期（很重要）：
      · 开奖前跑（推荐 20:30 前后）：最新开奖=昨天 → 目标期=今晚，当天的点位图正好用上；
      · 开奖后跑（21:35 以后）：最新开奖=今晚 → 目标期=明晚，而明晚的图还没发布，
        任务1.15 必然 exit 2、研报点位/三高必缺（今天 22:00 那轮就是这种情况）。

  夜间自动跑（开奖后，只跑不需要点位的模块）：

      python -m backend.pipeline.run_nightly_daily

  研究进度查看：

      python -m backend.utils.research_harness list

  一、数据同步与校验（全流程第 0~1 步，自动完成）
────────────────────────────────────────────────────────────────────────
  → 双源抓取：**中福彩 CWL 官方源为主源**，17500 为备源
     （2026-11 已调整；旧文档写的"17500 主源"是过期的，不要按旧口径排查）
  → 抓完必须校验：20 码完整、号码范围 1-80、期号 7 位、日期与期号对齐、按期号降序
  → 同步后自动刷新：热码统计 xlsx、跟随+点位+开奖数据.xlsx、012路/质合汇总 CSV

  A~F 六项校验（可单独执行）：

      python -m backend.utils.data_validator          # 只检查
      python -m backend.utils.data_validator --auto-fix   # 检查并自动修复

  六项里有任何一项不过，先修数据再往下走，不许带着脏数据跑预测。
  B0/B1 两步会自动自愈点位台账与三高手账（缩水检测 + 从备份重建）。


────────────────────────────────────────────────────────────────────────
  二、点位与三高录入（已并入全流程，自动完成）
────────────────────────────────────────────────────────────────────────

  【唯一动作】把当天的点位图 Excel 放进  validation\file\  ，什么都不用再敲。

    全流程「任务1.15」会自动：
      1. 扫 validation\file\ 里最新的 xls，逐个探测含「快乐8点位图」的工作表；
      2. 按期号块首行锚定目标期（下一行是站点占位标签，不是目标期）；
      3. 提取 K 列 20 码点位 + 重复高/边码左右翼/冷号高；
      4. 原子写 storage/raw/daily_points.txt 与 storage/points/tri_high_points.json。

    退出码（任务1.15 会翻译成人话打出来，不再静默跳过）：
      0 = 已对齐（或目录里没有 Excel，无需导入）
      2 = Excel 点位块还是旧的（不晚于最新开奖期）→ 不写库，研报亮缺口
      1 = 解析失败（多半放错了表：找胆图/统计图里没有「快乐8点位图」）
      3 = Excel 期号比开奖库超前 1 期以上 → 先同步开奖再导入

    单独排障（可选，不再是日常步骤）：

        scripts\auto_import_daily_excel.bat            # 手动单跑一次
        powershell -File scripts\import_daily_excel.ps1 -CheckOnly   # 只看解析结果不写库

    注意：旧版脚本会"目标期取不到就抓最近一条"，现在不会了——
    取不到就是取不到，宁可报缺口也不拿旧点位冒充当日点位。

  【方式 B：手动录入（备用，Excel 坏了才用）】

   ① 点位 20 码（必须恰好 20 个，1-80，不重复）：

       python scripts/input_daily_points.py \
              --points "01 04 05 09 20 24 25 32 44 45 52 55 56 57 64 70 72 74 75 77" \
              --period 2026303 --date 2026-11-13

   ② 三高（重复高任意条；边码严格左 4 + 右 4；冷号高一般 5~10 条）：

       在 Web 端「运维 → 三高录入」填写，或调用
       backend.modules.tri_high.tri_high_engine.TriHighResonanceEngine.save_record()

   落库位置（缺一不可，光贴文字不落库等于没录）：
      · 点位  → storage/raw/daily_points.txt
      · 三高  → storage/points/tri_high_points.json

   为什么必须落库：热码 RATIO 加权、Excel 点位底色、点位+遗漏、未开点位反弹、
   三高×点位共振、点位012偏态压缩器，全部从这两个文件读。

────────────────────────────────────────────────────────────────────────
  五、代码与逻辑体检（代码先行原则）
────────────────────────────────────────────────────────────────────────
  先体检再开跑。发现缺陷先指出问题、说清影响面、再修，修完重跑验证。

  重点排查项（每条都对应过一次真实事故）：
    · 有没有用历史号码/模板号码顶替当期缺口 —— 最高优先级，属伪造数据
    · 点位与三高是否按标准格式落库、目标期号有没有串期
    · status=retired 的模块是否还在参与出号或记账
      （判决源唯一：backend/core/module_gate.py 的 MODULE_SEED；
        查当前状态：python -c "from core.module_gate import retired_module_ids; print(retired_module_ids())"）
    · 路径有没有写死在已迁移的旧目录（数据文件都在 storage/raw/，
      统一用 backend.utils.paths.data_path()）
    · 残留 *.excel_lock 锁文件、Excel 被占用导致写失败

  修完必须物理验证：产物真实存在、>0 字节、字段齐全。
  不许只口头说「已修复」。


────────────────────────────────────────────────────────────────────────
  六、命中率与研究判定（预注册框架）
────────────────────────────────────────────────────────────────────────
  ⚠️ 先说清楚数学事实，避免白费力气：

    快乐8 每期 80 码开 20 码，每码概率恒为 25%，各期独立。
    对任意固定的 k 个号码，命中数服从超几何分布 ——
    **选哪 k 个号码都不改变命中分布**。定额选号不存在可优化空间。

  因此：
    · 不要再在 100 期样本上做网格搜索调参 —— 那个样本量最多分辨 6.2 个百分点的
      效应，而调出来的"提升"通常只有 2~3 个百分点，正好落在噪声里。
    · 任何"这次改动让命中率提高了"的说法，都必须走预注册框架才作数。

  预注册框架用法：

      python -m backend.utils.research_harness list
      python -m backend.utils.research_harness status <exp_id>
      python -m backend.utils.research_harness sync <exp_id> <module_id>

  规则（写死在 backend/utils/research_harness.py）：
    · 假设 / 唯一主指标 / 目标样本量 / 判死标准，**收数据前**写死并 SHA256 冻结
    · 未达目标样本量前，绝不判成功（100% 命中率也只显示 collecting）
    · 预设检查点只允许提前判死，不允许提前邀功
    · 判定只有四种：collecting / confirmed / rejected / inconclusive

  当前在跑的实验：sixteen_top3_hitrate（16期窗口中热主推 Top3，目标 500 期）


────────────────────────────────────────────────────────────────────────
  七、收尾
────────────────────────────────────────────────────────────────────────
  · 报告位置：storage/reports/（**data/ 根目录不再存放日报**）
  · 运行日志：storage/logs/（根目录 logs/ 会被自动归位到这里）
  · 提交推送：流水线结尾「任务7」自动把当日变更提交并推到 origin
        git push 不通时（github.com:443 被墙）自动改走 api.github.com 兜底
        关闭方式：AUTO_GIT_SYNC=0（全跳过） / AUTO_GIT_PUSH=0（只提交不推）
        默认是**开**（不设环境变量就是提交+推送），日志里会打 commit sha；
        如果看到「跳过: AUTO_GIT_SYNC=0」，说明是别的入口（Web/看板）带了这个变量，
        改在命令行跑，或先 set AUTO_GIT_SYNC=1 再跑。
  · 收工自检三句话：
        1) 任务1.15 是绿色「已按最新 Excel 对齐」，还是黄色 exit=2（表没更新）；
        2) 研报第五章「缺口清单」有没有点名；
        3) 任务7 有没有打出推送成功的 commit sha。


────────────────────────────────────────────────────────────────────────
  八、每天丢给助手的一句话模板（照抄即可）
────────────────────────────────────────────────────────────────────────
  推荐节奏：**当天 20:30 前后**（开奖前）把当天点位图放好，再发下面任一句。

  最省事版（Excel 已经放进 validation\file\ 了）：
      「跑今天全流程」

  带确认版：
      「今天 2026-11-27 的点位图已放进 validation\file\（2026317(2).xls），
        跑全流程，跑完把研报核心号码和缺口清单发我，记得提交推送。」

  没有新图版（照跑，但要接受点位/三高缺口）：
      「今天没新点位图，用现有台账跑全流程，缺口如实标出来。」

  只补跑版（比如白天表放晚了，晚上重跑）：
      「重跑 2026317 全流程，先看看任务1.15 有没有把新表导进去。」

  —— 助手收到后应做的事，按顺序：
      0) 确认 validation\file\ 里最新那份表是当天的（文件名/修改时间），
         以及现在几点：开奖前跑=预测今晚，开奖后跑=预测明晚（明晚的图还没发布）；
      1) cd data && python -m backend.pipeline.run_full_pipeline；
      2) 读 storage/logs/full_pipeline_<日期>.log，核对 1.15 退出码与任务7 的 commit；
      3) 物理读 storage/reports/全模块预测明细_<目标期>.md 与 复盘明细_<上期>.md，
         确认 >0 字节、章节齐全、缺口清单与日志口径一致；
      4) 把核心号码 + 缺口 + commit sha 报给用户。
