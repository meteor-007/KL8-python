# 夜间流水线健康告警 (Nightly Alerting)

> 2026-10-22 建立。起因：夜间自动流水线自 2026-09-20 起停摆一个月（计划任务路径失效 +
> 启动脚本缺 `sys.path` 自举），期间**没有任何告警**，等人工发现时已损失约 30 期数据。

## 一、它解决什么问题

| 故障形态 | 谁能抓到 |
| :--- | :--- |
| 任务跑了但**执行中崩溃** | 流水线进程内即时告警 (`_alert_on_failure`) |
| 任务**根本没启动** / 静默停摆 | Watchdog 扫描「多久没有一次 SUCCESS」 |
| Web 服务活着但夜间没跑 | Web 启动时的 watchdog 扫描 |

三者互补，任一存活即可发出告警。

## 二、默认行为（零配置）

不配置任何外部通道时，告警**仍然完整工作**：

- 落盘 `storage/alerts/alerts.jsonl`（追加式，永不丢失）
- 更新 `storage/alerts/latest_alert.json`（供前端/API 快速读取）
- 控制台打印
- 通过 `GET /api/quant/alerts` 暴露给前端

**绝不会因为"没配 webhook"就静默丢弃告警。**

## 三、接入外部通知（可选）

在项目根 `.env` 中追加即可，未配置的通道自动跳过：

### 钉钉 / 飞书 / 企业微信机器人

```ini
# 通用：程序按 URL 特征自动适配载荷格式
ALERT_WEBHOOK_URL=https://oapi.dingtalk.com/robot/send?access_token=xxxxx

# 仅钉钉加签机器人需要
ALERT_WEBHOOK_SECRET=SECxxxxxxxx
```

支持的 URL 特征：
- `oapi.dingtalk.com` → 钉钉 markdown（自动加签）
- `open.feishu.cn` → 飞书 text
- `qyapi.weixin.qq.com` → 企业微信 markdown
- 其他 → 通用 JSON（`{title, content, level, text}`）

### 邮件

```ini
ALERT_SMTP_HOST=smtp.example.com
ALERT_SMTP_PORT=465
ALERT_SMTP_USER=robot@example.com
ALERT_SMTP_PASS=********
ALERT_SMTP_TO=you@example.com
```

## 四、判据与阈值

```python
# backend/utils/nightly_watchdog.py
STALE_HOURS_DEFAULT = 26.0   # 超过 26h 无成功即判静默停摆
```

判定为异常的条件（任一命中）：

1. `last_status == "FAILED"` —— 显式失败
2. `last_status == "RUNNING"` 且持续 > 3 小时 —— 卡死
3. 距上次 SUCCESS > `stale_hours`（默认 26h）—— 静默停摆

> 26 小时的选择：彩票每日开奖，正常每天 22:00 跑一次；给 4 小时容差吸收
> 时区/补跑/人工干预，又能在一个自然日内发现断裂。

## 五、去重冷却

同一告警指纹（`key + title`）默认 **6 小时内只发一次**，避免计划任务重试刷屏。
恢复时自动清除失败指纹，使下次故障能重新告警。

## 六、命令行用法

```bash
# 单次体检（人读）
python -m backend.utils.nightly_watchdog

# 机器可读
python -m backend.utils.nightly_watchdog --json

# 只检查不告警
python -m backend.utils.nightly_watchdog --no-notify

# 自定义停摆阈值
python -m backend.utils.nightly_watchdog --stale-hours 30

# 查看告警通道配置自检
python -m backend.utils.alerting
```

## 七、API

| 接口 | 说明 |
| :--- | :--- |
| `GET /api/quant/alerts?limit=20&level=critical` | 读取告警记录 + 通道自检 |
| `GET /api/quant/nightly-health?stale_hours=26` | 夜间健康度体检（只读，不触发告警） |

## 八、独立于监控对象的部署建议

Watchdog 只读状态文件、不 import 夜间流水线，因此**即使流水线代码崩溃也能告警**。
若需要更强的抗毁性，可再挂一个 Windows 计划任务每日执行：

```
schtasks /Create /SC DAILY /TN "K8Quant_Watchdog" /ST 08:00 ^
  /TR "python -m backend.utils.nightly_watchdog"
```

早 8 点检查昨夜是否成功，异常则推送——这样即便整机夜间休眠也能在次日早上发现。
