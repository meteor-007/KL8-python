### 1.2 审计检查项（每条必须逐条检查并记录结果）

```
□ 路径硬编码：所有文件路径是否使用 utils/paths.py 统一管理？是否还存在硬编码路径？
□ 未来函数泄露：特征是否shift(1)封印？目标编码是否平滑？开奖列是否进入训练？
□ 统计检验缺失：AUC/命中率声称是否有p值支撑？是否做了Bonferroni校正？
□ 硬编码阶跃权重：是否替换为Tanh等连续平滑映射？
□ 前视污染：Excel开奖列是否错误进入推理数据？
□ fallback逻辑：target_issue无数据时是否fallback到latest_issue？（extract_rapid_blast、extract_special_5、deep_resonance_5、B3RightQualityChecker）
□ 环境识别阈值：hot_ratio阈值是否合理？是否几乎总是判为同一环境？
□ RW分量确定性：是否使用random.random()？应替换为数据驱动的确定性模型。
□ Excel锁机制：所有Excel操作是否通过excel_lock？锁超时是否60s？
□ 数据源1/2解析：Stride-4四维度All/50/25/10是否正确？带*号提取是否正确？
□ kjhyjsx优先：CWL API是否优先使用kjhyjsx（真实出球顺序）？
□ 17500 API fallback：返回500时是否正确fallback到CWL？
□ MK权重上限：是否超过0.35导致过拟合？
```

## ═══ 全局约束 ═══

### 执行优先级（严格按此顺序）

```
1.【代码审计与修复】→ 最高优先级，发现Bug必须先修复再继续
2.【数据采集与更新】→ 第二优先级，数据不完整则后续分析不可信
3.【执行引擎】→ 代码和数据都无问题后才执行
4.【结果输出与记录】→ 执行成功后输出和记录
```

### 数据安全底线

```
- 不删除、不覆盖 kl8_history_final.txt 和 daily_points.txt 的原始数据
- 修改代码前先备份
- Excel操作必须通过 excel_lock.py 获取文件锁
- 跟随+点位+开奖数据.xlsx容易损坏，异常时从backup/恢复
```

### 同日重复执行

```
- kl8_history_final.txt 幂等更新，可安全重复执行
- 若数据文件已确认今日最新，可跳过第二阶段
- 增量学习状态的 train_count 会累加，需标注
- AI记忆：同日仅更新不重复创建
```
