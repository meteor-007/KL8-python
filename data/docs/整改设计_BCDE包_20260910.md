## 0. 一件事放最前面：为什么 LSTM 还"活着"

上一轮整改只在两个地方说了"LSTM 已剥夺出号权"：
1. `backend/pipeline/run_nightly_pipeline.py` 把独立任务 `task35_lstm_engine()` 注释成了"精简下线"；
2. 日报引擎 `full_report_engine.py` 在研报里写了一句"已彻底剥夺出号表决权"。

但 LSTM 的肉体一刀没动：
- 每晚 `full_report_engine.py` 的研报段落仍在训练它并落盘 `outputs/predictions/prediction_{期号}.txt`；
- 共识引擎 `consensus_engine.py` 照旧收它的票，金胆还享受全系统最高权重 **2.5**；
- 5 个 API 端点 + 前端大屏 `aux_lstm.html` 全部照常服役；
- `run_lstm_daily.py` 独立入口随时可手动/被 API 触发。

**结论：当时是"文案下线"，不是"系统下线"。本次整改把这件事做真（见 B1）。**

## 1. 总架构：一个注册表管全家（新增 `backend/core/module_gate.py`）

系统里权重散在 20+ 处硬编码字面量里，谁也说不清"哪个模块凭什么在投票"。本次立一个唯一权威源：

**`backend/config/module_vote_registry.json`（模块投票注册表，每晚由流水线重新生成）**

每个模块记录：
```json
{
  "id": "lstm",
  "name": "双层LSTM",
  "status": "retired | observation | votable",   // 三态：退役 / 观察仓 / 有票权
  "vote_weight": 0.0,                             // 共识金胆投票权重
  "evidence": { "n_periods": 100, "lift": 0.98, "lift_ci_lo": 0.xx, "p_value": 0.xx, "bh_q": 1.0 },
  "reason": "30期实测Top10 Lift 0.98x 负贡献，418项挖掘证伪，投票权归零",
  "preregistered": null | { "hypothesis": "...", "frozen_rule": "...", "since": "..." }
}
```

**门禁规则（C6 新规）**：
1. 新模块上线 = 必须先预注册（写下假设 + 冻结规则），从上线之日起跑**前瞻账**；
2. **前瞻样本 < 200 期，一律进观察仓，投票权重 = 0**——可以运行、可以记账、就是不投票；
3. 满 200 期后，过 BH-FDR 多重检验（q<0.05）且 95%CI 下界 > 1.0，才准升"有票权"；
4. 有票权不是永久的：证据跌回基线，注册表下一晚自动降回观察仓。

共识引擎、进化引擎、看板一律只认这张注册表。**以后问"谁在投票"只查这一份文件。**

## 4. D 包（自进化：真做 vs 别演，同一原则=诊断常开、调参听门控、状态说人话）

系统自己的门控已判决"与随机不可区分"（197折 CI 下界 0.9906<1.0）。所以"真做"的正确含义是：**诊断（Loss 实算、证据入账）天天做；调参继续冻结，并把"为什么冻结"写明白**。这比硬开调参诚实，也比现在这种"predictions 记了、losses 永远空"的做戏诚实。

| 项 | 动作 |
|---|---|
| **D1** | `loss_weight_updater.update_with_actual` 拆成两段：**Loss 实算（诊断）永远在跑**——开奖后各算子交叉熵写进 `loss_history.json`；权重软最大更新留在门控后面。每条记录带 `weights_applied: false, blocked_by: "learning_gate"`。`get_current_weights` 返回权重来源说明。 |
| **D2** | ① `v3_trinity_audit.dynamic_meta_fusion` 返回值带 `weights_source`（learner / volatility_static_gate_frozen）；`save_memory` 把 `trinity_weights_source` 与 `learning_status` 写进 self_learning_state，界面可展示"当前权重=波动率静态兜底（自学习被门控冻结）"。② `learner_state.json` 加显式 `learning_status`；`learn()` 冷冻时仍跑诊断段；③ **Platt 校准补上真实现**（`_fit_platt`：对近 N 期 (score, hit) 对做两参数逻辑回归），纳进门控后的 learn 路径——platt_a/platt_b 不再是死字段；number_biases 更新代码留住（门控后照常），界面显示"偏差未激活（门控冻结）"而不是假装它在动。 |
| **D3** | `evolution_engine` 与 `master_reviewer` 里两份写死的 `DISCARDED_SUBSYSTEMS` 黑名单删除，改为读 module_gate 注册表：`status==retired` 的模块不参与准入、不上榜；evolution_state.json 的 `meta_weights/trinity_3d/fitness_history` 三个死字段删除并写入 `architecture_note` 说明；"一级共振决议权"改由统计显著性授予（见 B5）。 |
| **D4** | `get_evolution_status` 新增 `last_param_diff`（与上一代 ledger 对比：threshold/kill自/active/muted 哪些变了）；前端把"自进化模型当前代数 N"改名为"门禁迭代计数 N（非参数学习）"，旁边列出"本代真实参数变化：X 项"，学习被冻结时显著显示"自学习参数=冻结中"。 |

## 5. E 包（链路停摆）

核验结论先行：**E1/E2/E4 是误报**——unified_brain 决策 JSON、aggregation、outputs/predictions 都在随每晚流水线正常落盘（最新 2026242，昨晚 22:01）。真正停摆的只有 **E3（follow / gemini_pick2，停在 2026238）**，且是被有意注释"精简下线"的。

| 项 | 动作 |
|---|---|
| **E1/E2** | 无需修（审计误报，已钉钉验证）；把"每晚落盘检查"并入 E5 的新鲜度探针防止将来真停。 |
| **E3** | 两模块证据不足（follow 0.90x、gemini_pick2 质劣冗余），**正式退役**（不是复活）：注册表 `status=retired` + 退役日期；看板对应卡片显示"已退役 2026-09-03（证据不足）"而不是装作还在跑；陈旧 outputs 保留归档可查。 |
| **E4** | predictions/ 未停（被研报引擎持续写入），不归档；读它的退役交叉验证件按 B1 规则清理。 |

## 6. 验收口径（整改落地的定义）

1. `pytest` 全绿（新增 module_gate / consensus_registry / weekly_advisor / paper_trading 测试）；
2. 跑一次 `python run_master_review + evolution`（干跑脚本 `scripts/dry_run_remediate.py`）：榜上无编造数据、HE5 不再拿"一级共振决议权"、evolution_state 黑名单来自注册表；
3. `python -m backend.modules.aggregation.run_daily --force --review-n 30` 产出 JSON 里 LSTM/深层关联**不再出现在投票明细**，且带 `wf_validation` 审计块与"样本不足"水印；
4. `python -c` 调 `LossBasedWeightUpdater.update_with_actual`：门控冻结下 losses 字段真实写入、weights_applied=false；
5. `/api/health/freshness` 返回每链路新鲜度；follow/gemini 显示 retired；
6. 每周日 nightly 自动产出每周建议单；模块前瞻账有记录。
