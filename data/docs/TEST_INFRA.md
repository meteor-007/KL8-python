## 2. 4 层测试方法论详述与设计矩阵

### 2.1 Tier 1: 功能契约单点测试 (Category-Partition Testing)
- **目标**：验证五大物理特征提供器、统一主脑概率场、四级层级化出号决策、自进化损失引擎以及 Web 后端 API 的单点输入输出契约。
- **核心断言契约**：
  1. **特征输出形状与值域**：$F_{\text{time}}, F_{\text{space}}, F_{\text{rule}}, F_{\text{topo}} \in [0.0, 1.0]^{80}$，且 $F_{\text{mask}} \in \{\text{True}, \text{False}\}^{80}$；
  2. **概率场严格归一性**：主脑输出的 80 码全局概率向量满足 $\sum_{i=1}^{80} P(N_i) = 1.00000 \pm 10^{-4}$；
  3. **层级决策结构契约**：
     - 金胆（1码）：唯一确定整数 $g \in [1, 80]$；
     - 黄金选2（2码）：$[g, p]$，其中 $p$ 为与 $g$ 共现粘性最高的合法球，且 $p \neq g$；
     - 突击主力（5码）：包含 5 个互不相同的合法号码；
     - 8区底仓（12码）：包含 12 个互不相同的合法号码，且尽可能均衡覆盖 8 大物理分区（1-10, 11-20, ..., 71-80）；
  4. **自进化 Focal Loss**：损失值 $L > 0.0$，微调后参数在合法物理区间内（$\sigma \in [1.5, 4.0]$，$\lambda \in [0.85, 0.98]$）；
  5. **Web API 契约**：`/api/quant/unified-brain` 与 `/api/evolution/status` 响应状态码为 200，JSON 结构完整。

### 2.2 Tier 2: 极端边界与容错测试 (Boundary Value Analysis)
- **目标**：验证系统在面对极端开奖历史、极端超参数、奇异分布、空数据及脏数据输入时的稳健性与自愈能力，严防未捕获崩溃或除零错误。
- **设计矩阵**：
  | 测试用例场景 | 边界输入条件 | 预期系统行为与安全断言 |
  | :--- | :--- | :--- |
  | **空历史数据** | 开奖列表为空 `[]` | 优雅返回默认特征结构，主脑解算平稳降级为先验均匀分布，不报 `ZeroDivisionError` 或崩溃 |
  | **超短历史** | 仅有 1 期或 3 期开奖 | 窗口自适应缩短，平稳提取特征，计算概率 |
  | **坏行与脏数据容错** | 文本中混杂乱码、空行、少于 20 个球的残缺行 | 加载器自动过滤异常行，提取合法行并保持期号升序 |
  | **极端高斯核宽 $\sigma$** | $\sigma = 0.01$ (极窄点状) 与 $\sigma = 50.0$ (全域泛化) | $\sigma \to 0$ 时仅点源有微弱能量，$\sigma \to \infty$ 时能量平坦扩散，所有特征值在 $[0, 1]$ 内无 NaN/Inf |
  | **极端时序衰减 $\lambda$** | $\lambda = 0.0$ (只看上期) 与 $\lambda = 1.0$ (无衰减) | 时序动量正常加权并归一化，无溢出 |
  | **极高温与极低温 $T$** | $T = 0.05$ (极低冷凝) 与 $T = 50.0$ (极高温) | 玻尔兹曼概率分布平滑计算，极低温逼近独热 argmax，极高温逼近均匀分布，求和皆为 1.0 |
  | **全雷区一票否决上限** | 雷区掩码设为 25 码（极限规模） | 25 码概率绝对归零，剩余 55 码重新归一化分配概率，四级决策中 100% 不包含任何被杀号码 |
  | **空规则激活态** | 当期没有命中任何顺口溜或反弹规则 | $F_{\text{rule}} = \vec{0}$，主脑平稳退化为纯时空+拓扑物理驱动，不影响正常推演 |

### 2.3 Tier 3: 跨特征组合与闭环协同测试 (Pairwise Combinations & Feedback Loops)
- **目标**：验证五大物理特征的非线性物理共振机制、杀号硬势垒与高能候选球冲突时的绝对阻断效力、以及“推演 ➔ 残差 ➔ 进化 ➔ 再推演”的参数微调自洽性。
- **设计矩阵**：
  | 测试用例场景 | 交叉组合特征配置 | 验证核心逻辑 |
  | :--- | :--- | :--- |
  | **时空超线性共振** | ① 时序高 + 空间高<br>② 时序高 + 空间低<br>③ 时序低 + 空间高<br>④ 时序0 + 空间0 | 验证共振势能 $\sqrt{F_{\text{time}} \cdot F_{\text{space}}}$：只有时空双高时触发强烈超线性共振；单高时共振消失，平缓叠加；双 0 时共振势能为 0。 |
  | **杀号硬势垒（已退役）** | KillSeeker 已拆除 | `DefenseMaskExtractor` 恒全安全；默认不启用硬势垒。主口径为最优 3 码。 |
  | **拓扑伴随顺藤摸瓜** | 金胆确定后，不同候选号码拥有不同的共现粘性 | 黄金选2的搭档球选择必须综合考虑候选球自身概率与同金胆的共现粘性得分 $P \times (1 + \ln(1 + \text{co\_score}))$，选出最强连体婴。 |
  | **8区空间均衡覆盖** | 前 5 码全部挤在第 1、2 分区（1-20 号） | Top 12 决策算法能够智能跨越未覆盖分区，从剩余安全球中挑选代表号码，实现 8 大物理分区均衡防守。 |
  | **自进化连续迭代稳定性** | 模拟 5 期连续开奖残差自适应反向微调 | 验证代数连续累加（$G \to G+1 \to \dots$），参数在安全边界内自适应微调，总账本记录完整。 |

### 2.4 Tier 4: 全流程端到端业务工作流测试 (Workload Scenarios)
- **目标**：以真实生产环境方式调用 CLI 脚本、FastAPI 后端路由，检验系统从数据同步到推演落盘、API 查询及前端渲染契约的全流程闭环。
- **全流程覆盖**：
  1. **主脑独立推演工作流**：执行 `python -m backend.modules.unified_brain.run_daily`，物理检查 `outputs/unified_brain/unified_decision_*.json` 与 Markdown 研报生成；
  2. **自进化独立工作流**：执行 `python -m backend.modules.unified_brain.run_evolution_daily`，物理检查 `storage/evolution/unified_evolution_ledger.json` 账本与参数更新；
  3. **Web API 真实端点黑盒调用**：通过 FastAPI TestClient 请求 `/api/quant/unified-brain`、`/api/evolution/status` 等，验证 JSON Schema 与数据一致性；
  4. **前端大屏消费数据契约**：检验推演数据与自进化日志是否具备前端 Web 驾驶舱雷达图、80码热力图渲染所需的全部字段。

## 4. 测试运行指令与验收标准 (Execution & Acceptance Criteria)

### 4.1 快速全量测试命令
```powershell
# 运行全量 E2E 测试套件并输出详细日志
pytest tests/e2e/ -v -s

# 单独运行某个层级的测试
pytest tests/e2e/test_e2e_features.py -v
pytest tests/e2e/test_e2e_boundary.py -v
pytest tests/e2e/test_e2e_combinations.py -v
pytest tests/e2e/test_e2e_workloads.py -v
```

### 4.2 质量红线与验收准则
1. **0 失败 0 报错**：所有 4 个层级的测试用例必须 100% 通过（Exit Code 0）；
2. **物理守恒律**：概率场总和必须严格为 1.0，杀号雷区号码在推荐清单中占比严格为 0；
3. **真实资产落盘校验**：测试执行后必须物理读取并验证产物文件的存在性与合法性；
4. **大白话语义无违和**：测试用例说明与报告必须通俗易懂，符合老派量化操盘手实战纪律。
