# data PRD

## AI 速读卡

- 产品一句话：基于 FO（Fusion-Oracle）单通道基线的 KL8 号码评分系统，通过 Walk-Forward 验证门控和学习冻结机制确保推荐可靠性。
- 核心循环：历史+点位数据加载 → 环境识别 → FO 信号评分 → 随机对照 → Walk-Forward 回测 → 学习门控判定 → 推荐/冻结。
- 目标平台：Windows PowerShell / Python 3.10+ 命令行工具。
- 硬约束：Walk-Forward Lift ≤ 1.1 时冻结所有参数更新；FO 信号为主通道，其余通道仅 weekly 监控；随机对照种子=目标期号确保可复现。
- 推荐默认：FO 单通道 daily 输出；train_window=50/val_window=10/step=10/min_history=80；Lift 阈值=1.1。
- 发挥空间：信号通道扩展、环境识别特征迭代、FO 评分公式优化。
- P0 验收：`python main_v2.py` 在含≥80期历史数据的目录下执行，输出 FO Top20 + 随机对照 + Walk-Forward 报告 + 学习门控状态。
- 最容易翻车：WF Lift≈1.00 恰好基线导致学习永久冻结；Hurst指标已移除 随机基线环境识别失效；Excel 文件锁定冲突。
- 超预期机会：多通道 Lift 监控仪表盘；环境识别动态权重可视化；Walk-Forward 滚动热力图。

## 第一章：产品概述

data 是一款 KL8 量化基线系统，让数据分析用户能够基于 FO 信号通道获取号码评分和推荐，并通过 Walk-Forward 验证和学习门控确保推荐可靠性，而无需担心过拟合和参数漂移。

### 1.1 差异化对比表

| 功能 | 传统频率分析 | 通用量化框架 | 本产品 |
|---|---|---|---|
| 信号通道 | 单一频率统计 | 需自定义 | 内置 7 通道（FO/EF/RW/MK/EO/BAYES/MC），FO 为主通道 |
| 验证方法 | 无或简单回测 | 需自定义 | Walk-Forward 时序交叉验证（黄金标准） |
| 过拟合防护 | 无 | 需手动配置 | 学习门控：WF Lift ≤ 1.1 冻结所有参数更新 |
| 随机对照 | 无 | 需自定义 | 可复现随机对照（种子=目标期号），每期对比 |
| 环境识别 | 无 | 需自定义 | 5 类环境（热号/冷号/平衡/趋势/混沌）自动识别 |
| 多重检验 | 无 | 需手动配置 | FDR-BH 校正选主信号通道 |
| Excel 集成 | 手工操作 | 需自定义 | 自动读取 Excel 点位+开奖数据，格式化输出 |

### 1.2 三类用户画像

**用户 A：日常分析使用者**
- 核心目标：每天获取 FO 信号推荐和随机对照，验证推荐有效性
- 对现有工具最大的不满：没有可靠的验证机制，不知道推荐是否真的比随机好
- 让他们愿意切换的那一个功能：Walk-Forward 验证 + 随机对照 + 学习门控

**用户 B：量化研究者**
- 核心目标：研究不同信号通道在 KL8 中的 Lift 表现，验证通道组合策略
- 对现有工具最大的不满：缺乏多通道对比和 FDR 校正
- 让他们愿意切换的那一个功能：7 通道 weekly 监控 + FDR-BH 主信号选择

**用户 C：聚合系统开发者**
- 核心目标：获取 FO 评分接入 V18.0 共识聚合器
- 对现有工具最大的不满：接口不稳定，缺乏环境状态标记
- 让他们愿意切换的那一个功能：稳定 FO API + 环境识别 + 学习门控状态

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| FO 单通道 daily 推荐（核心能力） | 深度学习模型（数据量不足，已验证无效） |
| Walk-Forward 时序验证（过拟合防护） | 实时预测（特征依赖完整历史，非实时场景） |
| 7 通道 weekly 监控（通道对比） | 自动通道选择（FDR 校正仅选主信号，不做自动切换） |
| 学习门控冻结（参数安全） | 跨彩种适配（架构专为 KL8 80选20 设计） |
| 环境识别 5 类（市场状态感知） | GUI 界面（定位为 CLI 工具） |
| Excel 数据集成（点位+开奖读取） | 在线数据源对接（仅读取本地文件） |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| WF Lift ≤ 1.1 时冻结参数更新 | FO 为 daily 主通道 | 信号通道可扩展 |
| 随机对照种子=目标期号 | train_window=50/val_window=10/step=10 | 窗口参数可调 |
| FDR-BH α=0.05 选主信号 | min_history=80 | FDR 阈值可调 |
| FO 评分不可为零（防止归零退化） | Lift 阈值=1.1 | Lift 阈值可调 |
| Excel 文件读取使用锁机制 | 环境识别 5 类 | 环境特征可扩展 |
| Walk-Forward 严格时序无泄露 | max_primary=2 主信号 | 主信号数量可调 |

## 第四章：超越竞品的差异化功能

### 第 4.1 节 学习门控冻结机制

**竞品为何没有这个功能**：传统系统要么完全不做参数更新（固定参数），要么无限制地做自动调参（容易过拟合）。通用 ML 框架虽有早停机制，但不会基于全局 Walk-Forward Lift 做系统级冻结决策。

**本产品如何实现**：学习门控模块 `learning_gate.py` 读取 Walk-Forward 全局 Lift，当 Lift ≤ 1.1 时冻结所有参数更新（param_store、闭环权重、Loss 更新）。冻结状态持久化到 `learning_gate_state.json`，确保跨进程一致。只有当新的 Walk-Forward 回测 Lift > 1.1 时才解冻。

**风险与应对**：
- 风险：KL8 随机基线环境中 Lift 永远 ≤1.1，学习永久冻结。应对：这是设计意图——"不作为胜过乱作为"（祭司原则），在不可预测的市场中保持基线参数是最安全策略。
- 风险：冻结状态下无法应对市场状态变化。应对：环境识别模块仍然运行，策略配置会根据环境调整，只是参数不更新。

### 第 4.2 节 可复现随机对照

**竞品为何没有这个功能**：传统系统不提供随机对照基线，用户无法判断推荐是否真的优于随机。通用框架虽有随机基线，但通常不可复现。

**本产品如何实现**：随机对照使用目标期号作为随机种子 `rng = random.Random(target_issue)`，确保同一期号的随机对照结果完全可复现。每期输出 FO Top20 和随机 Top20 并排对比，用户可直接看到 FO 相对于随机的优势。

| 库名 | 用途 | 为何优于替代方案 | 大致包体积 |
|---|---|---|---|
| numpy | 数组运算 | 科学计算基石 | ~15MB |
| openpyxl | Excel 读写+格式化 | 纯 Python，跨平台 | ~5MB |
| scipy | 二项检验 | 统计检验标准 | ~40MB |
| pandas | DataFrame（可选） | 数据处理标准 | ~35MB |

**最大架构风险**：`feature_optimizer.py` 直接读取 Excel 文件且依赖单元格样式（颜色/边框）判断点位和开奖，Excel 格式变更会导致解析失败。应对建议：迁移到纯文本格式（daily_points.txt + kl8_history_final.txt）作为主数据源，Excel 仅作辅助。

**可替换技术原则**：推荐 numpy + openpyxl 栈；如果项目已用 polars 可替换 pandas；不可变的是 FO 信号评分逻辑、Walk-Forward 验证框架、学习门控 Lift>1.1 判定逻辑。

## 第十一章：开发者交接说明

### a) 实现顺序建议

1. **先建历史数据加载器**：实现 `kl8_history_final.txt` 解析，确保按期号降序排列。这是一切的基础。
2. **再建 FO 信号评分**：实现 `feature_optimizer.py` 的 Layer A 评分，先从纯历史频率开始，逐步加入点位交叉。
3. **然后建随机对照**：实现可复现随机基线（种子=目标期号）。
4. **接着建 Walk-Forward 验证器**：实现 50/10/10 配置的时序交叉验证。
5. **最后建学习门控**：读取 WF Lift，判定冻结/解冻状态。

### b) 最可能导致返工的三个决策

**决策 1：FO 评分公式设计**
- 安全默认：基于 Excel 数据的频率+遗漏+点位交叉（当前实现）
- 需改变方向的信号：WF Lift 持续 < 0.9，说明 FO 评分不如随机
- 风险：Excel 依赖导致格式变更时解析失败

**决策 2：Walk-Forward 参数配置**
- 安全默认：train=50/val=10/step=10（当前实现）
- 需改变方向的信号：Fold 间 Lift 方差 >0.3，说明窗口太小不稳定
- 风险：窗口太大导致 Fold 数量不足

**决策 3：学习门控 Lift 阈值**
- 安全默认：1.1（当前实现，有意偏严）
- 需改变方向的信号：冻结超过 100 天且市场出现明显趋势，可能需要临时解冻
- 风险：降低阈值会导致过拟合参数更新

### c) 哪里要严格，哪里可以灵活

| 章节 | 约束/建议 | 原因 |
|---|---|---|
| Walk-Forward 时序无泄露 | 约束 | 验证可信度的基础 |
| 学习门控 Lift>1.1 判定 | 约束 | 防止过拟合参数更新 |
| 随机对照种子=目标期号 | 约束 | 可复现性保证 |
| FO 为主通道 | 约束 | 多通道融合引入过拟合风险 |
| FO 评分公式 | 建议 | 可根据回测结果优化 |
| Walk-Forward 窗口参数 | 建议 | 可根据数据量调整 |
| 环境识别特征 | 建议 | 可扩展新特征 |
| 通道评分函数 | 建议 | 可优化各通道算法 |

### d) 已知的未知项

1. FO 评分公式的具体细节在 `feature_optimizer.py` 中超过 500 行，Layer A 评分的完整数学公式是否最优待验证。
2. 7 个信号通道均未通过 FDR 校正——是 KL8 本身不可预测还是通道算法需要改进，这是核心未知项。
3. Excel 文件依赖是架构风险——长期是否应完全迁移到纯文本格式待决策。
