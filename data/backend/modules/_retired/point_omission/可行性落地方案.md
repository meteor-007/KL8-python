## 1. 项目背景与目标

### 1.1 背景

快乐8（KL8）每期从 01–80 中开出 20 个号码（无放回、等概率）。用户每日手选 20 个"核心点位"，希望系统结合历史开奖，把**点位场**与**遗漏号**（一段时间未开出的号码）结合起来，给出结构化研判与推荐。

《思路.txt》要求对"深度分析四重奏"（连号集群、周期共振、场域能量、反向博弈）外加马尔可夫/隐马尔可夫、斐波那契、线性代数/SVD、复变/傅里叶、图网络、波动率聚类、余数空间、熵值、对抗生成等"十大高价值方案"进行综合研判，最终输出 N 维评分仪表盘、Top 5、宏观趋势、风险预警、决策树、5+2 终极推荐。

### 1.2 目标

构建独立项目，每期：

1. 读入 20 个核心点位 + 历史开奖；
2. 按 `[前一位, 点位, 后一位]` 循环扩展（01↔80 环绕），形成拓展点位集合；
3. 计算拓展集合中每个号码的近 10 期命中、近 3 期命中、连失次数；
4. 运行十大分析方法，各自产出可解释的指标与候选号码打分；
5. 融合为 H1–H7 七维评分，排出 Top 5；
6. 生成结构化 Markdown 报告，覆盖任务清单全部条目；
7. 配套真实点位档案回测与随机基线对照，量化每个方法的真实增量，防止过拟合。

### 1.3 可行性结论

- **数据可行（已就位）**：`Python-Project/data/` 下已有 **2063 期开奖（2020-10-28 起）+ 278 期历史点位档案**，格式规整。其中 **277 期**能与开奖严格配对（1 条脏记录，见 §2.6），使**真实回测**而非模拟回测成为可能。增量缺口可由双源 API 自动补齐。
- **算力可行（但需实测）**：80 号空间下，共现矩阵 80×80、SVD、协方差、FFT、马尔可夫转移矩阵等都是小规模线性代数，单期全量分析预计在秒级。但全档案回测需对每个历史期重跑完整流水线，**v1.0 断言的"278 期回测 < 1 分钟"未经实测，v2.0 撤回该断言**，改为在阶段 2 做性能基线实测（§12.3）。
- **方法可行（全部自研）**：十大方法均可用 numpy/scipy 标准实现，无外部算法依赖。所有模块从零编写，工作量已计入 §14 路线图。
- **诚实性约束**：快乐8 开奖近似独立同分布，任何"规律"都可能是随机噪声。本系统定位为**结构化决策辅助与娱乐性分析**，不承诺盈利。所有方法必须通过真实档案回测 + 随机基线对照证明其相对随机的增量，否则权重置零（§9）。

### 1.4 定位与前提（重要）

本系统存在一个**根本张力**，必须在设计中正面处理而非用免责声明糊过去：

> 如果开奖序列真是 i.i.d.，那么这套系统的**期望输出就是随机数**，任何"研判"都没有预测力。

本方案的处理方式是把它变成一个**可证伪的设计**，而不是回避：

1. **每个方法都必须自行证明增量**：通过 §9.1 的滚动外样本回测，与 §9.2 的同口径随机基线比较；未通过者权重清零。
2. **系统级降级路径**：若全部方法都被清零（这是 i.i.d. 假设下的**预期终局**），报告必须显著标注"本期推荐与随机选取无统计差异"，§7 的终极推荐降级为"娱乐性随机示例"。详见 §9.5。
3. **价值主张随之明确**：系统的价值不在于"预测中奖号码"，而在于——把用户已有的点位直觉，用一致、可复现、可审计的方式结构化呈现，并诚实地标出哪些信号经不起检验。

用户应当清楚：**这套系统最可能诚实的结论是"没有可检测的规律"**，而这本身是有价值的结论。

## 2. 输入数据规范

### 2.1 核心点位文件 `daily_points.txt`

**实际位置（已实测核实）**：`C:\D-pan\Dpanqianyi\Python-Project\data\daily_points.txt`，278 期，2025-11-26 → 2026-09-09，UTF-8 无 BOM，CRLF 换行。

格式（每期一行，最新在前）：

```
date:2026-06-11,period:2026152,points:04 10 12 14 16 20 22 27 30 38 39 40 54 59 62 65 70 74 75 80
```

手动录入时接受纯号码（无前缀，由系统补全目标期号与日期）：

```
04 10 12 14 16 20 22 27 30 38 39 40 54 59 62 65 70 74 75 80
```

- `date`：YYYY-MM-DD
- `period`：7 位 = 4 位年份 + 3 位年内序号（如 `2026152`）
- `points`：20 个号码，空格分隔，两位零填充（01–80）
- 解析后去重、排序、校验范围 1–80、**数量必须恰好 20**

### 2.2 历史开奖文件 `kl8_history_final.txt`

**实际位置（已实测核实）**：`C:\D-pan\Dpanqianyi\Python-Project\data\kl8_history_final.txt`，**2063 期，2020-10-28 → 2026-09-09**，UTF-8 无 BOM，CRLF 换行。

```
date:2026-06-10,period:2026151,numbers:12-24-44-36-06-49-70-10-73-03-52-21-04-45-37-38-77-41-42-78
```

- `numbers`：20 个号码，**短横线 `-` 分隔**（与点位文件的空格分隔不同）
- 多期连续，最新在前
- 金额格式兜底（CSV/JSON）见 §8

### 2.3 期号语义（关键约束）

期号 = **年份 + 年内序号**，年内序号**每年重置**（`2020001` 与 `2021001` 并存）。

推论（必须遵守）：

1. 期号**全局唯一**，可作主键去重；
2. 期号**数值不连续**是正常的——实测 11 处日期缺口全部对应春节（约 11 天）与国庆（约 5 天）休市，**不是数据缺失**；
3. **禁止用 `period + 1` 推断下一期**——跨年时会得到不存在的期号（2026 年最后一期 `2026351`，加一得 `2026352`，实际应为 `2027001`）；
4. 任何时序排序与截断**以日期为准**，不以期号算术为准。

### 2.4 扩展规则（循环三元组）

对每个核心点位 `p`：

```
prev = p-1 if p > 1 else 80
next = p+1 if p < 80 else 1
expanded = {prev, p, next}
```

20 个点位 → 至多 60 个号码（去重后通常 40–58 个）。01 的前一位视为 80，80 的后一位视为 01。

### 2.5 拓展集合基础统计

对拓展集合中每个号码 `n`（`T` = 可用历史期数）：

| 量 | 定义 | 说明 |
|---|---|---|
| `hit10` | 近 10 期中出现次数 | 0–10 |
| `hit3` | 近 3 期中出现次数 | 0–3 |
| `miss` | 连失次数：由最近一期往前数连续未开出的期数；最新一期命中则 0 | ≥0 |
| `freq_full` | 全样本出现次数 | 0–T |
| `exp_hit` | 全样本期望 = `T × 20/80` = `0.25T` | 单期每号命中概率 0.25 |
| `std` | **理论标准差 = `√(T × p × (1−p))`，`p = 0.25`** | 见下方说明 |
| `z_score` | `(freq_full − exp_hit) / std` | 热度偏离 |

**关于 `std` 的关键说明（v1.0 的重大缺陷）**：v1.0 只写"std"未定义求法。若实现者按"跨号经验标准差"计算，在本数据上会灾难性失败——实测 2063 期里每个号的出现次数高度集中在 `0.25 × 2063 ≈ 515.75` 附近，跨号经验 std 趋近于 0，`z_score` 会爆炸成无穷大。

正确做法是用**理论二项标准差** `√(T·p·(1−p))`。T=2063 时 std ≈ 19.67，z_score ∈ 约 [−3, +3]，有界且可比。

> 注意：该定义下各号的 z_score 差异本身就不大——**这恰恰是 i.i.d. 数据的真实面貌**，不是 bug。方案不通过人为放大来制造"信号"。

### 2.6 数据体检（加载后强制执行）

§8 的数据源加载完成后，`source.py` 必须输出一份体检报告，并据此决定可用样本：

```

```

### 3.6 数值稳健性契约

v1.0 完全没有处理退化输入。实测数据规模下（278 期 × 80 号 ≈ 2.2 万次估计），以下场景几乎必然触发：某号从未开出、某号期期开出、某期只有一个号、拓展集合为空。

**统一规定**（`numerics.py` 提供工具函数，所有模块必须使用）：

| 场景 | 处置 |
|---|---|
| 分母为 0 或 < ε | 该项计 `0.0`，不得产生 nan/inf |
| `log(x)` 且 x ≤ 0 | 记 0（该号跳过该子项），并在 `diagnostics` 计数 |
| 样本量不足（如该号历史命中 < 30 期） | 该号整体降级，score = 0.0，标 `insufficient_data` |
| SVD/矩阵秩亏 | 降阶或返回零向量，不抛异常 |
| 拟合不收敛（Weibull/HMM） | 捕获，回退到简单估计，`sufficient=False` |
| 卡方/比例检验期望频数 < 5 | 改用 Fisher 精确检验或跳过 |

`test_numerics.py` 必须用全 0 序列、全 1 序列、单期历史、空拓展集合等退化输入断言：**不抛异常、不产生 nan/inf、所有 score ∈ [0,1]**。

### 3.7 随机性与可复现

系统含多处随机过程：随机基线（1000 次重采样）、HMM 的 EM 随机初始化、图社区发现、Exp3 探索采样。

**规定**：

1. `config.yaml` 的 `reproducibility.seed` 为全局唯一种子，通过 `np.random.default_rng(seed)` 派生各模块的子 rng 并显式传入。
2. 禁止在模块内直接调用 `np.random.*` 全局函数。
3. 报告与回测产物记录本次 `seed`、代码版本、数据快照的期号范围。
4. §10.3 的回归门禁必须**在同一 seed 下比对确定性数值**，否则会因随机基线波动而随机红绿（v1.0 的门禁设计有此缺陷）。

## 4. 十大分析方法 · 逐一落地设计

### 4.0 统一约定

每个模块实现 §3.5 的 `analyze(...) -> ModuleResult`。所有分数：

- 定义域 1–80，**拓展集合外的号码恒为 0.0**；
- 模块**内部**先算出原始量（可能是任意量纲），再在**拓展集合内**做归一化（算子由 `config.thresholds.norm_method` 决定，默认 rank 归一，对无界量更稳健）；
- 归一化后必须落在 [0,1] 且为有限值。

> **v1.0 的缺陷**：全文档没有任何归一算子定义，而 H1 的 z_score、H2 的 Weibull 危险率、H3/H5 的邻居数都是无界量，直接相加无法保证值域。v2.0 统一为"模块内先归一，融合时只做有界量的加权"。

**每个模块都必须给出显著性诊断**（`diagnostics`），因为本系统的前提是"方法必须自证增量"（§1.4）。无显著性的方法照样输出分数，但融合时会因权重为 0 而不影响结果，并在报告中标注。

---

### 4.1 连号集群行为 Cluster Dynamics（`cluster.py`）

**目标**：识别连号（相邻整数）与集群（2 连、3 连、4+ 连）的成团倾向与回补规律。

**算法**：

1. **连段扫描**：每期开奖号排序后扫描连续段。`[12,13]` 为 2 连段，`[38,39,40]` 为 3 连段。
2. **连段频率与显著性**：统计最近 N 期（N=30/60）各类连段出现次数 `f_k`（k=2,3,4+）。
   - 期望 `E_k` 与标准差 `σ_k` 用 **Monte Carlo 估计**：在 i.i.d. 零假设下（每期从 80 中均匀抽 20）模拟 10000 次，得到 `f_k` 的零分布均值与标准差。**不使用解析组合公式**（v1.0 写了 `E_k/std` 但从未给出求法，实现者无法计算）。
   - `cluster_z_k = (f_k − E_k) / σ_k`，双侧检验，α 由配置给出，多重比较用 Bonferroni 校正（k 只有 3 档，校正后阈值 ≈ α/3）。
3. **三元组场分析**（与点位扩展天然契合）：统计每个形如 `{p−1, p, p+1}` 的三元组在历史的"成团命中数"（三元组中至少 2 个同期开出）。
4. **打分**（拓展集合内 rank 归一）：
   - 所在三元组近 10 期成团命中数越高 → 该集群越活跃；
   - 该号是否处于"未补的连号缺口"（如 `12,13` 常出但 `11` 长期缺 → `11` 有回补预期）。

**数值稳健**：N 期不足 30 时 `sufficient=False`，全表记 0。

**评分贡献**：→ H3。

---

### 4.2 周期性共振与波段节奏 Cyclic Patterns（`cyclic.py`）

**目标**：检测号码出现的周期性与"波段"（连续活跃 vs 连续沉默）。

**算法**：

1. 对每个号码建 0/1 时序 `x_n[t]`（1 = 该期开出）。
2. **前置白噪声检验**：先对 `x_n` 做 **Ljung-Box 检验**（lag=20）。未通过者（p > α）直接判定"无周期结构"，`T_n = None`，**不进入后续步骤**。
   > v1.0 缺失此步，导致纯噪声也被强行找周期。
3. **自相关**：`acf_n(k) = Σ(x[t]−x̄)(x[t−k]−x̄) / Σ(x[t]−x̄)²`，k = 1..20。
   - 显著性阈值用 **Bonferroni 校正**：`|acf| > z_{α/(2·20)} / √N ≈ 2.81/√N`（α=0.05）。
   - v1.0 用未校正的 ±1.96/√N，在 20 个 lag 上至少出现一个假显著的概率约 **64%**——约 50 个号里会有 32 个被噪声授予"显著周期"，直接污染 H4 与报告"主导周期"。
4. **周期估计**：取校正后仍显著的 lag 中的**最高峰**作为 `T_n`。无显著峰则 `T_n = None`。
5. **波段节奏**：统计连续 1 的游程与连续 0 的游程长度分布，与几何分布（i.i.d. 下的理论分布）做**拟合优度检验**（卡方，期望频数 < 5 的格子合并）。识别"过度聚集"。
6. **周期共振群**：仅对 `T_n ≠ None` 的号码做 `T_n` 的模运算聚类（如多个号的 `T_n ≈ 7`）。**v1.0 在这步用了未校正的 `T_n`，是污染的主要入口**；v2.0 限定为校正后仍显著的号码。
7. **打分**：处于共振群 + 当前相位接近峰值的号码得分高。相位定义：`phase_n = (t mod T_n) / T_n`，仅对 `T_n ≠ None` 的号有效。

**评分贡献**：→ H4（与 §4.8 做几何平均前的先合并，见 §4.14 注）。

---

### 4.3 数字场域能量分布图 Heat Zone Mapping（`heatmap.py`）

**目标**：把 1–80 划分为场域，可视化能量分布。

**算法**：

1. **多尺度场域**：
   - 8 段（每段 10 号）：`[1-10], [11-20], …, [71-80]`
   - 4 象限（20 号/象限）
   - 余数 8 区（mod 8，与 §4.11 呼应）
2. **能量密度**（v1.0 未区分"密度"与"计数"，导致期望口径歧义）：
   - 定义 `d_zone` = **单期平均命中数** = `(窗口内该场域总命中数) / 窗口期数`
   - 期望 `E_zone = size_zone × 20/80 = size_zone / 4`（单期）
   - 能量比 `r = d_zone / E_zone`
3. **场域偏向指数** `bias = max(r) − min(r)`，衡量冷热不均。
4. **打分**：落在"低能量但历史回补活跃"场域的号码得分高（能量反转逻辑），在拓展集合内 rank 归一。

**输出**：场域能量表 + Markdown 热力矩阵（10 行 × 8 列）。

**评分贡献**：→ H4、H7。

### 4.4 反向心理博弈模型 Contrarian Insight（`contrarian.py`）

**目标**：当多数模块一致看好某号码时，反向评估其"拥挤"风险。

**这是一个元模块**，接口见 §3.5（消费其他模块的 `scores`）。

**算法**：

1. **共识度**：`consensus[n] = mean_{m ∈ 主分方法集} scores_m[n]`。
   - **主分方法集**明确为 11 个同构模块（`cluster, cyclic, heatmap, markov, fibonacci, linalg_svd, complex_fft, graph_net, volatility, remainder, entropy`），**排除 contrarian 自身与 adversarial**。
   - v1.0 写"收集其他九大模块"但实际有 12 个其他模块，口径错误会导致共识度算错。
2. **拥挤度**：`crowd[n] = consensus[n]`。
3. **质量门控**（v1.0 只写"引入质量门控"但未给阈值）：
   - 门控条件：`omission_z_rebound[n] ≥ config.contrarian_gate_z`（默认 0.5）**且** `crowd[n] < config.contrarian_veto`（默认 0.75）。
   - 通过者得 `contrarian[n] = 1 − crowd[n]`；未通过者 `contrarian[n] = crowd[n]` 的**反向否决标记**（记入 `metrics.vetoed`，不进候选）。
4. **输出"反向候选"清单**：被多数模块忽视、但遗漏结构合理的号码。

**评分贡献**：**不进 H1–H7 主分**（避免与其他模块双重计数）。作为 §5.4 备防两码的候选来源，以及报告 §四"拥挤"预警的内容来源。

---

### 4.5 马尔可夫链状态转移 + 隐马尔可夫（`markov.py`）

**目标**：用状态转移建模号码的冷热轮转；用 HMM 捕捉不可观测的"市场状态"。

#### 4.5.1 状态定义（v1.0 在此处有致命缺陷）

**v1.0 错误**：用"近 10 期命中次数"定义状态 S0–S3。这是一个 **9 期重叠的滑动窗口**，导致相邻两期的状态按构造只能相差 −1/0/+1——转移矩阵退化为严格带状。数值复现（i.i.d. p=0.25，2000 步）显示：16 个可能转移只出现了 9 个，`S2↔S3` 各只出现 2 次（因为 `P(Bin(10,0.25) ≥ 7) = 0.0035`）。这种转移矩阵是窗口的**确定性副作用**，不是可学习的轮转规律。

**v2.0 修正**：改用**遗漏长度**分档。这是一个真正的首达过程：

```
状态定义（按当前连失期数 m）：
  S0 : m = 0        （上期命中）
  S1 : m ∈ [1, 2]
  S2 : m ∈ [3, 5]
  S3 : m ∈ [6, +∞)  （长遗漏）
```

转移结构天然健康：从任意状态 `S_k`，下期要么命中 → `S0`（概率 `p_k`），要么未中 → 遗漏 +1（进入下一档或留在 S3）。链条干净、可估计、无滑动窗口伪影。

**核心信号假设**：若 i.i.d. 成立，则各档的命中概率应**恒等于 0.25**。估计 `p_k = (该档总命中次数) / (该档总暴露期数)`，用**比例检验**比较 `p_k` 是否显著偏离 0.25。这是本模块的真正检验对象，直接对应"遗漏号是否真会回补"这一用户核心关切。

3. **转移矩阵**：`P[a][b]` 由上述结构直接估计（行和 = 1，天然满足）。对 S3 做**拉普拉斯平滑**避免样本过少导致的估计不稳。
4. **一步预测**：`π_{t+1} = π_t · P`，得每个号码下期处于各状态的概率。
5. **HMM（可选增强）**：
   - 隐状态 = 市场情绪（冷静/活跃/动荡），观测 = 每期全场特征（连号数、跨度、熵）。
   - 优先用 `hmmlearn.GaussianHMM`；不可用时降级为纯马尔可夫（`sufficient=False` 标注）。
   - 估计当前隐状态，据此调整冷热偏好。
6. **打分**：`markov_score[n] = P_{t+1}(n ∈ S2 ∪ S3)` 加权 + HMM 状态调整因子，拓展集合内 rank 归一。
7. **诊断**：输出各档 `p_k` 与 0.25 的检验 p 值。**若全部档位都不显著偏离 0.25，报告应明说"遗漏回补效应未检出"**。

**评分贡献**：→ H6。

### 4.6 斐波那契数列分析（`fibonacci.py`）

**目标**：用黄金分割与斐波那契数识别"自然回补位"。

**诚实性前置声明**：斐波那契与黄金分割对均匀随机序列**没有理论支撑**（不像 §4.5 的遗漏过程有首达结构）。本模块默认权重低（在 H1 中占低权子项），且**必须通过回测显著性检验才保留**，否则清零并在报告中标注"已停用"。这是 §1.4 原则的直接应用。

**算法**：

1. **斐波那契集**：`F = {1,2,3,5,8,13,21,34,55}`（取 ≤ 80 的元素）。对 > 80 的（如 89）取 `mod 80` 补回并去重。
   - v1.0 同时写了"（>80 截断）"与"及其 mod 80 投影"，两者矛盾（截断则 89 被删，投影则 89→9 保留）。v2.0 明确：**取 ≤80 的元素，并对 >80 者取 mod 80 补回，最后去重**。
2. **黄金分割锚点**：`anchor = floor(80 × r)`，`r ∈ {0.382, 0.5, 0.618, 0.786}` → `{30, 40, 49, 62}`。
   - v1.0 用 0.764，非标准回撤位；标准为 `√0.618 ≈ 0.786`。v1.0 虽给了"≈30、49、61"，但 0.764 的取值本身是错的，v2.0 一并修正（62 而非 61）。
3. **冷热识别**：统计斐波那契号集 vs 非斐波那契号集的近 N 期命中率，做**比例检验**（期望频数 < 5 时改 Fisher 精确检验）。
4. **打分**：斐波那契号 **且** 处于回补窗口（`miss ≥ 该号历史中位连失`）→ 加分。纯斐波那契巧合不给分。

**评分贡献**：→ H1 低权子项 + 决策树"顺势"分支的辅助过滤。

### 4.7 线性代数与矩阵分析（`linalg_svd.py`）

**目标**：共现矩阵、协方差矩阵、SVD 分解、条件概率，揭示号码间结构。

**算法**：

1. **共现矩阵** `C[80][80]`：`C[i][j]` = 两号同期出现次数（§6.2 的底座复用同一对象，不重复计算）。
2. **Jaccard** `J[i][j] = C[i][j] / (f_i + f_j − C[i][j])`（分母为 0 时该项记 0）。
3. **PMI** `= log( C[i][j]·N / (f_i·f_j) )`，`C[i][j] = 0` 时跳过（避免 `log(0)`）。
4. **协方差矩阵**：每期作为 80 维 0/1 向量，`Σ = Cov(X)`。主对角即方差，非对角即协同波动。
5. **SVD**：对**列中心化**的命中矩阵 `X[T×80]` 做 `X = U S Vᵀ`。
   - **v1.0 的矛盾**：既按列中心化（减去了每号均值 = 热度），又说"`Vᵀ[0]` 常反映全场热度公共因子"——中心化恰好消掉了热度，第一主成分不可能再是热度。v2.0 明确：**保留列中心化用于结构分析，但不再声称第一成分是热度因子**（热度已由 H1 单独承担）。
   - **符号固定**：对每个右奇异向量，令其绝对值最大的分量为正，保证跨实现可复现。
6. **条件概率**：`P(B开出 | A开出) = C[A][B] / f_A`，用于"跟随"筛选。
7. **打分（v1.0 量纲错误，已修正）**：
   - v1.0：`score = 载荷 × 邻居数`——载荷无量纲、邻居数是计数，相乘后由计数支配，量纲不一致。
   - v2.0：`score[n] = Σ_{j≤k} |V[n, j]| · PMI_norm(n)`，其中 `PMI_norm(n) = Σ_{m ∈ 拓展集合, PMI(n,m)>0} PMI(n,m)` 先归一化到 [0,1]。两项均为有界量，量纲一致。

**评分贡献**：→ H5（与 §4.9 在维度内聚合）。

### 4.8 复变函数分析（`complex_fft.py`）

**目标**：把号码命中序列映射到频域/复平面，提取频域特征。

**v1.0 的缺陷**：构造 `z[t] = x_n[t] + i·y_n[t]`（x 是 0/1，y 是场域能量）。但 `arg(z) = atan2(y, x)`，当 `x = 0`（约 75% 的期数）且 `y > 0` 时，**相位恒等于 π/2**，与 y 的取值完全无关。相位序列退化成常数加跳变，谈不上"旋转趋势"，`x=0` 时"相位上扬"无法判定。

**v2.0 修正**：

1. **主路径（纯 FFT，与 §4.2 互验）**：
   - 对实序列 `x_n[t]` 做 `np.fft.rfft`，取功率谱 `P[k] = |X[k]|²`。
   - **前置**：仅对 §4.2 中通过 Ljung-Box 的号码做谱分析（否则纯噪声也能得到"主频"）。
   - 主频 `k*` = 谱峰位置；谱平坦度 `SF = 几何均值 / 算术均值`，`SF → 1` 表示白噪（无周期）。
2. **解析信号路径（可选，替代 v1.0 的无依据复数构造）**：
   - `z[t] = hilbert(x_n[t])`（`scipy.signal.hilbert`），得解析信号。
   - `|z[t]|` = 瞬时幅度包络；`unwrap(arg(z[t]))` = 展开相位。
   - **"相位上扬"的可计算定义**：`d(phase)/dt > 0` 且持续 ≥ 3 期（v1.0 只写"接近上扬"，无定义）。
3. **相位共振**：多个号主频一致且相位差 < π/4 → 共振群。
4. **打分**：主频显著 + 相位一阶差分 > 0 的号得分高；谱平坦（白噪）不加分，记 0。

**数值稳健**：`x_n` 全 0 时 `hilbert` 返回全 0，相位未定义 → 该号记 0。

**评分贡献**：→ H4（与 §4.2 在维度内先做几何平均合并，见 §4.14）。

### 4.9 图网络关系挖掘（`graph_net.py`）

**目标**：号码当节点、共现/PMI 当边权，挖掘"中心号"与"团块"。

**算法**：

1. **建图**：80 节点，边权 = PMI（仅保留正 PMI 且超过配置阈值的边，得稀疏图）。
2. **中心性**：度中心性 / 特征向量中心性。高中心性 = "枢纽号"。
3. **社区发现**：Louvain / greedy modularity（`networkx`）。识别号码社区。
4. **随机游走重启 RWR**（底座见 §6.2）：以拓展集合为种子，`r = α·r·W + (1−α)·seed`，迭代至收敛，得每号"亲和分"。
5. **桥接号**：betweenness 高的号连接多个社区。
6. **打分**：亲和分 + 中心性 → 拓展集合内 rank 归一。

**降级**：`networkx` 不可用时退化为 numpy 邻接矩阵的度中心性，`sufficient=False` 标注。

**性能注意**：betweenness 是 O(V·E)，80 节点可接受；但**全档案回测会在每期重算**，必须缓存社区结构或降低重算频率（§12.3）。

**评分贡献**：→ H5（与 §4.7 在维度内聚合）。

### 4.10 波动率聚类分析（`volatility.py`）

**v1.0 的两个致命问题**：
1. 递推式 `σ²[t] = ω + α·r[t−1]² + β·σ²[t−1]²` 把方差又平方，四次量纲，参数不可辨识；
2. 更根本的是，**对 0/1 伯努利序列套金融 GARCH 本身就不适用**——`r[t] = x[t] − x̄` 只有两个取值，`r²` 亦然，在给定 p 下条件方差恒为 `p(1−p)`，根本没有"连续波动"可建模。且 `r²` 是 `x` 的确定性变换，`Ljung-Box(r²)` 实际检验的是 `x` 自身的自相关，与 §4.2 重复。

**v2.0 修正**：改用与伯努利匹配的量。

1. **二项过度离散检验**：对每个号码，用滑动窗口 `W=30` 统计各窗口命中数 `h_w`。
   - i.i.d. 零假设下 `h_w ~ Bin(30, 0.25)`，期望 `7.5`，方差 `5.625`。
   - 检验统计量：`D = Σ(h_w − 7.5)² / 5.625`，在零假设下近似 `χ²`（自由度 = 窗口数 − 1）。
   - `D` 显著大于自由度 → **存在过度离散（波动聚集）**。
2. **游程拟合优度**（与 §4.2 共用实现）：连续未出的游程长度对几何分布做卡方检验。
3. **打分**：过度离散显著 **且** 当前处于"活跃簇"（近期窗口命中数高于中位数）→ 加分。
4. **风险联动**：高波动号同时进入报告 §四的风险预警。

**评分贡献**：→ H4 波动子项 + 风险预警。

### 4.11 余数空间映射 + 周期共振（`remainder.py`）

**目标**：把号码按 `mod m` 映射到余数环，检测失衡与周期。

**v1.0 的两个缺陷**：

1. **期望算错**：统一用 `20/m`。但 80 只能被 8 和 10 整除，**m = 12 时桶大小为 6 或 7、m = 13 时亦然**。实测桶分布：m=12 → 7 个桶各 7 号、5 个桶各 6 号；m=13 → 2 个桶各 7 号、11 个桶各 6 号。用 20/12 = 1.667 会把"桶更大"误判为超命中，系统性偏移失衡指数。
2. **桶定义二义**：原文"`r = n mod m`（注意 80 视为 0 或 m）"——若把 80 视为 m，m=8 时产出余数 8，落在合法区间 [0,7] 之外，凭空多一个桶。

**v2.0 修正**：

1. `m ∈ {8, 10, 12, 13}`；映射 `r = n mod m`（**80 → 0，不引入 m**）。桶大小 `size(r) = |{n ∈ [1,80] : n mod m = r}|`。
2. **单期期望** `E_r = size(r) × 20/80 = size(r) / 4`（m=12 时为 1.5 或 1.75；m=8 时为 2.5）。
3. **失衡统计量**（比 v1.0 的比值更严谨）：
   ```
   z_r = (obs_r − N·E_r) / √(N · E_r · (1 − size(r)/80))
   ```
   其中 `obs_r` = N 期该余数类总命中数。
4. **周期共振**：统计"同一余数类连续 N 期超/欠命中"的模式。
5. **打分**：处于"严重欠命中余数类"（`|z_r| > config.remainder_z_alert`）且该类历史回补快的号码加分。

**评分贡献**：→ H7、H3。

### 4.12 熵值评估与分布均衡度监控（`entropy.py`）

**v1.0 的硬错误**：定义 `p_i = freq_i / 20`。但 `freq_i` 是**全样本出现次数**，其总和 `Σfreq = 20T`。因此 `Σp = 20T/20 = T = 2063 ≠ 1`——**根本不是概率分布**。

实测后果：`H_num = −Σ p ln p = −6705.97`（负数），`H* = H_num / ln 80 = −1530.33`，与同段宣称的 `H* ∈ [0,1]` 直接矛盾。若退一步按"单期指示"理解（`p_i = 1/20`），则 `H_num ≡ ln 20`、`H* = ln20/ln80 ≈ 0.684` **恒定**，毫无区分度。两种解释下输出都是错的，且错误结论会写进报告第三章。

**v2.0 修正**：

1. **号码熵**：`p_i = freq_i / Σ_j freq_j`（等价于 `freq_i / (20T)`）。
   - `H_num = −Σ p_i ln p_i`，`H* = H_num / ln 80`，此时 `H* ∈ [0,1]` 成立（实测 ≈ 0.9998）。
2. **场域熵**：8 段场域命中分布的熵，衡量场域均衡。
3. **滑动熵**：30 期滑窗的熵序列，用 `config.entropy_low_quantile`（默认 10% 分位）判定"低熵异常有序期"。
4. **KL 散度**：本期分布 vs 历史分布，异常大则告警。
5. **打分**：熵偏低（有序）时，集中于少数场域的号更可能延续；熵偏高（均衡）时转向回补冷号。

**评分贡献**：→ H7 + 宏观趋势"熵值异常"。

### 4.13 对抗生成思维（`adversarial.py`）

**目标**：系统自我反驳——对每个候选号生成"为什么不该选它"的反证，做熵值校正与稳健性筛选。

**v1.0 的缺陷**：要求逐号判断"过拟合：它在回测外样本表现如何""随机性：它的得分是否落在随机基线波动内"，但 §9.1/§9.2 只定义了**组合级**指标（Top5 命中率、5+2 分布），没有任何逐号接口，也没有给出"反证得分"的合成公式与阈值 → 门控无法实现。

**v2.0 修正**：定义四个**可计算**的逐号反证指征，各归一化到 [0,1]（越大 = 反证越强）：

| 指征 | 定义 | 数据来源 |
|---|---|---|
| `refute_crowd` | 该号在其他模块中的共识度（越拥挤越可疑） | §4.4 `consensus[n]` |
| `refute_overfit` | 该号在**滚动外样本**中的命中 lift 是否低于 1（截止 t−1 估计，不需要目标期数据） | 新增 per-number 外样本接口，§9.4 |
| `refute_random` | 该号得分在"随机基线零分布"中的分位（分位越低越可疑） | 新增 per-number 零分布，§9.2 |
| `refute_phase` | 该号当前周期相位是否处于下行 | §4.2 / §4.8 |

**反证得分**：`refute[n] = 加权平均(四个指征)`，权重在 `config` 中给出（默认等权）。

**门控**：仅 `refute[n] < config.adversarial_refute_max`（默认 0.5）的号可进入终极推荐。

**熵值校正**：若候选集合过于集中于单一方法或单一场域（多样性熵低于阈值），强制引入对冲号。

**降级路径**：若逐号外样本接口尚未实现（阶段早期的正常情况），本模块降级为**仅输出反证文字、不作门控**，并在报告中标注。这比 v1.0 的"定义了无法实现的门控"更诚实。

**评分贡献**：不进 H1–H7 主分，作为终极推荐的最后一道过滤器。

### 4.14 方法—维度映射总表

明确三类方法集，全文计数口径统一（v1.0 在"十大方法"与 13 个模块间口径混乱，且 §4.4 误写"其他九大模块"）。

| 类 | 成员 | 数量 | 作用 |
|---|---|---|---|
| **主分方法集** | ①cluster ②cyclic ③heatmap ⑤markov ⑥fibonacci ⑦linalg_svd ⑧complex_fft ⑨graph_net ⑩volatility ⑪remainder ⑫entropy | **11** | 产出 scores，参与 H1–H7 融合 |
| **对冲方法集** | ④contrarian | 1 | 不进主分；产出备防候选与拥挤预警 |
| **过滤方法集** | ⑬adversarial | 1 | 不进主分；终极推荐门控 |
| 底座（非方法） | omission、cooccurrence | — | 为上述方法提供共享计算 |

**维度内聚合规则**（v1.0 未定义，是实现者无法确定融合次序的主因）：

```
H_k[n] = Σ_{m ∈ dim(k)} w_m · score_m[n]  /  Σ_{m ∈ dim(k)} w_m
```

| 维度 | 收录方法 | 聚合方式 |
|---|---|---|
| H1 热度 | fibonacci（低权子项）+ 基础统计 z_score/hit10 | 加权平均 |
| H2 遗漏反弹 | omission（Weibull 危险率 + Z 反弹） | 加权平均 |
| H3 集群 | cluster + remainder（余数团块子项） | 加权平均 |
| H4 周期/波动 | cyclic、complex_fft **先几何平均**，再与 heatmap、volatility 加权平均 | 两级聚合 |
| H5 共现/图 | linalg_svd + graph_net | 加权平均 |
| H6 马尔可夫 | markov（含 HMM 调整） | 直接 |
| H7 熵/均衡 | entropy + heatmap（均衡子项）+ remainder（均衡子项） | 加权平均 |

**几何平均的 0 值处理**（v1.0 未定义，任一子项为 0 会整体归零）：

```
geo(a, b) = √( (a + ε) · (b + ε) ) − ε,   ε = 1e-3（配置项）
```

## 5. 评分与推荐

### 5.1 唯一的融合链路（v1.0 有两处互相矛盾的定义）

**v1.0 的缺陷**：§5.2 写 `composite = Σ_k w_k·H_k[n]`，§6.3 又写 `composite = Σ_method w_method·score_method[n]` 再"投影到 H1–H7"。两处同名、方向相反；而且"由标量 composite 投影出 7 维 H"在数学上不可能。同时 §5.1 说 H 权重可被 Exp3 覆盖，§6.3 说 Exp3 更新的是方法权重——方案对"Exp3 到底学哪层"自相矛盾。

**v2.0 固定为三段式，全文档只此一条路径**：

```
第 1 段（方法层）  score_m[n] ∈ [0,1]          由 11 个模块各自产出
        │
        ▼  维度内聚合（§4.14）
第 2 段（维度层）  H_k[n] ∈ [0,1]              k = 1..7
        │
        ▼  维度加权（w_k 由 config.scoring.weights 给出，和为 1）
第 3 段（综合分）  composite[n] = Σ_k w_k · H_k[n] ∈ [0,1]  → 百分制 ×100
```

**Exp3 学的是方法权重 `w_m`**（第 1 段的维度内权重），**不是** `w_k`。

- 理由：方法层是可归因的（能回答"是哪个方法在起作用"），维度层只有 7 个臂、且语义是用户偏好而非可学习量。
- v1.0 的 §5.1"H 权重可由 Exp3 覆盖"表述**已删除**。
- 维度内聚合时，`w_m` 先由 Exp3 更新，再按 §4.14 的规则归一，使 `H_k` 仍落在 [0,1]。

### 5.2 H1–H7 七维定义

| 维度 | 名称 | 构成（§4.14） | 归一化 | 默认权重 |
|---|---|---|---|---|
| H1 | 热度 | `z_score`（§2.5）+ `hit10` + fibonacci 低权子项 | rank | 0.18 |
| H2 | 遗漏反弹 | omission 的 Weibull 危险率 + Z 反弹分 | rank | 0.18 |

| H5 | 共现/图 | linalg_svd + graph_net 加权平均 | rank | 0.12 |
| H6 | 马尔可夫 | markov（含 HMM 调整因子） | rank | 0.12 |
| H7 | 熵/均衡 | entropy + heatmap 均衡子项 + remainder 均衡子项 | rank | 0.12 |

合计 1.00。

**归一化算子**（v1.0 缺失，v2.0 统一）：默认 **rank 归一**——在拓展集合内按原始值排序，映射到 `[0,1]`。选择 rank 而非 min-max 的理由：H1 的 z_score、H2 的 Weibull 危险率、H3/H5 的邻居数都是无界量，且对极端值敏感；rank 归一对其天然稳健，且保证 H_k 的分布形状在各维之间可比。

## 6. 底座模块规格

三个底座为多个方法提供共享计算。**全部自研**，接口如下。

### 6.1 `omission.py` — 遗漏分析

```python
def analyze_omission(draws: list[Draw],
                     expanded_set: set[int],
                     cfg: Config) -> ModuleResult   # → H2
```

**产出**：

1. **连失追踪表**：每号的当前连失 `m`、历史中位连失、最大连失、连失分布。
2. **Weibull 危险率**：对每号的历史连失长度拟合 Weibull（`scipy.stats.weibull_min`），得 `h(m) = (k/λ)·(m/λ)^(k−1)`，`m` 为当前连失期数。
   - 拟合失败（样本 < 30 或数值不收敛）→ 回退到经验危险率 `h(m) = 命中次数 / 暴露期数`，标 `sufficient=False`。
3. **Z 反弹分**：`z = (m − μ_miss) / σ_miss`，其中 `μ_miss`、`σ_miss` 为该号历史连失长度的经验均值与标准差（**注意与 §2.5 的 `std` 不同**：这里是连失长度的分布，不是出现次数的二项分布）。
4. **输出**：`omission_score[n]`（Weibull 危险率与 Z 反弹分的加权 rank 归一）→ H2；同时导出 `omission_z_rebound[n]` 供 §4.4 门控使用。

### 6.2 `cooccurrence.py` — 共现与图底座

```python
def build_cooccurrence(draws: list[Draw], cfg: Config) -> CooccurrenceBundle
```

**产出**（供 §4.7、§4.9 共享，**只算一次**）：

- `C[80][80]` 共现计数矩阵
- `J[80][80]` Jaccard
- `PMI[80][80]` 点互信息（`C=0` 处为 0）
- `RWR(seed_set, alpha)` 函数：以拓展集合为种子的重启随机游走，返回亲和向量

**性能**：共现矩阵在全档案回测中**不应每期重算**——采用增量更新（减去滑出期、加上新期），见 §12.3。

### 6.3 `ensemble.py` + Exp3 在线权重

**Exp3 的精确定义（v1.0 全部缺失，导致无法实现）**：

| 项 | 定义 |
|---|---|
| **臂（arm）** | 11 个主分方法（不是 7 个维度，也不是 13 个模块） |
| **每臂的下注** | 该方法的 `scores` 在拓展集合内的 **top-5 号码**（与系统 Top5 同规模，保证可比） |
| **奖励（reward）** | `(命中数 − 1.25) / 1.25`，其中 1.25 = 随机期望，命中数 = 该臂 top-5 与本期实际开奖的交集大小。**归一化后中心在 0**：正 = 优于随机，负 = 劣于随机 |
| **更新频率** | 每期一次（所有臂同时更新），使用**截止上一期**的开奖结果 |
| **权重下限** | `weight_floor = 0.01`（**不置 0**）。v1.0 说"不显著则权重清零"，但清零后该臂永远无法恢复——Exp3 的标准做法是保留探索概率，故 v2.0 改为下限而非归零 |
| **"停用"的表现** | 权重落到下限的方法，在报告中标"已停用（未跑赢随机）"，但仍在每期获得 1% 的探索预算，以便环境变化后能恢复 |
| **冷启动** | 前 `warmup_periods = 60` 期用 `config` 中的默认等权；60 期后切换到 Exp3 学习到的权重 |
| **预热衔接** | 实盘启动时，先用历史档案跑 60 期回测重建权重状态（与 §9.1 共用同一套回测代码），再进入实盘 |

**奖励用 top-5 命中的理由**：方法输出的是 1–80 的连续打分，没有天然的"命中/未中"二元结果。用 top-5 命中数把它折算成与系统输出同口径的标量，才能公平比较。

### 8.3 点位录入规格

**解析**（自研，兼容混排输入）：

```python
def parse_points_input(raw: str) -> list[int]:
    # 1. 中文标点归一：，、； 全角 → 半角空格
    # 2. 其余分隔符（空格/逗号/分号/连字符/竖线/制表符/换行）→ 空格
    # 3. re.findall(r"\b\d+\b") 提取整数
    # 4. 过滤 1..80、去重、升序
```

**校验**：恰好 20 个、范围 1–80、无重复，返回 `(bool, msg)`。

**目标期号与日期的推断（v1.0 的跨年 bug）**：

参考实现用的是 `target_period = latest_hist_period + 1`。由于期号是"年份 + 年内序号"（§2.3），这在**跨年时会得出不存在的期号**（2026351 + 1 = 2026352，实际应为 2027001）。

**v2.0 修正算法**：

```
1. 下一交易日 = 开奖库中 date > latest_hist_date 的最小 date
   （若无 → 用 latest_hist_date + 1 天，并标注"日历未知，已回退"）
2. 目标期号：
     若 下一交易日 的年份 == 该年已有期号的最大年份:
         target = (年份, 该年最大年内序号 + 1)
     否则:   # 跨年
         target = (新年份, 1)        → 20YY001
3. 禁止任何形式的裸 period + 1
```

### 8.4 解析鲁棒性与写回规格

- **字段锚定解析（v1.0 的正则误用）**：v1.0 §8.4 把 `re.split(r'[\s,\-、，]+', s)` 作为整行解析器。该正则作用于 `date:2026-06-10,...` 会把日期切成 `['date:2026','06','10',...]`，也会把 `numbers:` 里的短横线当字段分隔符。
  **v2.0 规定两段式解析**：
  ```
  1. 用锚定正则提取字段值：
       date   ←  date:([0-9\-]+)
       period ←  period:(\d+)
       payload←  (?:points|numbers):(.+)$
  2. 仅对 payload 做分词：re.split(r'[\s,\-、，]+', payload)
  ```
- **编码**：统一用 `encoding='utf-8-sig'` 读取，同时兼容有 BOM（种子 CSV）与无 BOM（两个共享 txt）。
- **换行（v1.0 因果写反）**：
  - 实测两文件是**纯 CRLF**。
  - v1.0 说"写出时必须显式 `newline='\n'`，否则会变成 `\r\r\n`"。**成因写反了**：`\r\r\n` 只在"内存字符串已含 `\r\n` 且以默认 newline 写出"时出现。而按默认(通用换行)读入后内存里是 `\n`，此时用 `newline='\n'` 写出得到的是 **LF**——即把共享文件从 CRLF **改成 LF**，破坏格式契约。
  - **v2.0 规定**：读取用文本模式；写出时统一 `newline=''` 并**显式拼接 `'\r\n'`**，保持共享文件的 CRLF 契约。`test_data_io.py` 用**字节级往返断言**验证换行符不漂移。
- **期号校验**：去重、按 `int(period)` 逆序排序、检测日期倒挂（告警不阻断）。
- **号码校验**：1–80、去重、每期恰好 20 个；异常行标 `dirty` 并跳过，计入报告告警。

### 8.5 并发与共享目录安全

**风险**：`mode: read_write` 下，本系统与 Python-Project 会写同一个文件。实测结论：

- Windows 下，目标文件被另一进程以普通 `open()` 打开时，`os.replace(tmp, target)` 会直接抛 `PermissionError [WinError 5]`。
- 参考实现（两侧）都是"读全部 → 重写全部"，且**都未加锁**。
- 因此 v1.0 在风险章节提出的缓解手段 `msvcrt.locking` **无效**——锁只约束加锁者自己打开的字节区间，对不协作的对方进程没有约束力；而 `os.replace` 替换的是目录项，旧文件上的锁毫无意义。

**v2.0 规定**：

| 级别 | 规则 |
|---|---|
| **默认** | `mode: read_only`。系统只读共享目录，所有写入（抓取的新期、录入的点位）落在**本项目 `data/cache/` 下的副本**上 |
| **写回共享** | 仅在用户显式设 `read_write` 时启用。写回前：① 重读目标文件并比对 hash，若与上次读取不一致（说明对方已改）→ **放弃本轮写回**并告警；② 走 §8.2 的原子写回；③ `PermissionError` → 退避重试 3 次，仍失败则降级为写副本 + 告警 |
| **对账** | 每期运行后比对"共享文件期数"与"上次运行记录"，若**减少**则说明被覆盖，立即告警并在报告中显示 |
| **永不** | 不修改共享文件的**历史行**，只做追加 |

**理由**：默认只读把"损坏 2063 期档案"的风险降到零，而增量抓取的价值完全可以通过写副本实现（副本再供分析使用）。需要写回时用户显式开启并承担对账责任。

## 9. 验证方法论与诚实性

### 9.1 为什么这一章是硬约束

11 个方法全部是在**同一份历史数据上搜索模式**。在没有严格验证纪律的情况下，几乎必然产出"看起来有效"的结论——因为 80 选 20 的样本空间里，任何方法都能找到历史巧合。v1.0 完全没有定义"什么叫验证通过"，这是最严重的方法论缺陷。

本章定义三件事：**怎么回测**（9.2–9.4）、**怎么判断有效性**（9.5–9.7）、**无效时怎么办**（9.8–9.9）。

### 9.2 真实回测循环（277 期）

**关键优势**：`Python-Project/data/` 同时提供开奖历史（2063 期）与点位档案（278 期，其中 277 期可配对），因此可以做**真实历史回测**，不需要模拟数据。这是本项目相对"只有思路文件中 30 期样例"的最大改进。

```
pairings = §2.6 配对出的 (period_P, date_P) 列表，按期号升序     # 277 项
records  = []
for P, date_P in pairings:
    # ① 只喂 P 之前的数据 —— 无前视的核心
    hist_P   = [d for d in history if d.period < P]         # 严格小于
    points_P = points_archive[P]                            # 第 P 期当日点位
    if len(hist_P) < cfg.warmup_periods:                    # 默认 60
        skipped += 1; continue

    # ② 完全按实盘路径算分
    expanded = expand(points_P)                             # §2.4
    base     = compute_base_stats(hist_P, expanded, cfg)     # §2.5，用 hist_P 重算
    result   = analyze_all(hist_P, expanded, cfg)            # §3.5
    top5     = select_top5(result, cfg)                      # §5.3
    picks    = select_52(result, cfg)                        # §5.4

    # ③ 与第 P 期真实开奖对照
    actual = draw[P]
    records.append({
        "period":          P,
        "top5_hits":       len(set(top5)       & set(actual)),
        "core5_hits":      len(set(picks.core) & set(actual)),
        "defensive_hits":  len(set(picks.def)  & set(actual)),
        "expanded_hits":   len(set(expanded)   & set(actual)),
        "points20_hits":   len(set(points_P)   & set(actual)),
        "per_method_hits": {m: len(set(result.top5_of(m)) & set(actual))
                            for m in MAIN_METHODS},
    })
```

**三条不可违反的纪律**：

| 纪律 | 含义 | 违反示例 |
|---|---|---|
| **严格小于** | 预测第 P 期只允许用 `< P` 的期次 | 用 `<= P` 会把当期开奖喂进模型 |
| **每期重算** | `base_stats`、马尔可夫状态、Exp3 权重必须在每个 P 上从 `hist_P` 重新计算 | 用全量历史算一次 `hit10` 再套 277 期，等于每期都知道未来 |
| **配置冻结** | 回测期间 `config` 不得依据回测结果调整权重/阈值 | 回测中调参 → 结果不可复现且系统性乐观 |

**性能与纪律的冲突**：全程重算是 O(T²)。唯一允许的优化是**增量维护**（§12.2），但增量状态必须可证明等价于重算——由 `test_incremental_equivalence`（§10.2）验证。任何不等价的"优化"视为违反纪律。

### 9.5 双基线

单看"Top5 命中 1.4 个"没有意义，必须与基线比较。定义两条：

| 基线 | 抽样方式 | 期望命中 | 回答的问题 |
|---|---|---|---|
| **B1 拓展集合内随机** | 从 `expanded`（40–58 个）中均匀抽 5 个 | 1.25 | 系统是否胜过"只在点位拓展集里瞎选" |
| **B2 全 80 随机** | 从 01–80 中均匀抽 5 个 | 1.25 | 拓展集合本身是否携带信息 |

两条基线的**期望值相同**（无论怎么选，5 个号对 20 个开奖号的命中期望都是 `5 × 20/80 = 1.25`），但必须都算，因为还有第三个更关键的量：

```
lift_sys = mean(top5_hits)     / 1.25
lift_exp = mean(expanded_hits) / E_expanded,   E_expanded = |expanded| × 20/80
lift_pts = mean(points20_hits) / 5.0,          E = 20 × 20/80 = 5.0
```

`lift_exp` 回答一个独立且优先的问题：**"点位拓展集合"这个输入本身有没有超过随机的信息量？** 若 `lift_exp ≈ 1`，则无论后面 11 个方法怎么算，系统都不可能真正有效。这一条必须在报告中单独披露，且应当在 MVP 阶段首先测出来（§14.2）。

### 9.6 统计检验

每期命中数 `H ~ 超几何(N=80, K=20, n=5)`：

```
E[H]   = 5 × 20/80 = 1.25
Var[H] = n · (K/N) · (1 − K/N) · (N−n)/(N−1)
       = 5 × 0.25 × 0.75 × 75/79 ≈ 0.8900
SD[H]  ≈ 0.9434
```

**必须是超几何，不是二项。** v1.0 用 `√(n·p·(1−p))` 是二项假设，忽略了"无放回"，会高估方差约 `(N−1)/(N−n) ≈ 1.054` 倍，使检验偏保守、并让功效结论失真。数值差异虽小，口径必须正确。

**T 期汇总**：`SE = SD[H] / √T`，单样本 z 检验：

```
z = (mean_hits − 1.25) / SE        H0: mean_hits = 1.25（无预测力）
```

**多重比较校正**：11 个主分方法各自算 lift，若逐个用 α=0.05 判"有效"，在完全无效的系统上期望仍有 `11 × 0.05 ≈ 0.55` 个方法"显著"。必须校正：

- 控制族错误率：**Bonferroni**，`α_i = 0.05/11 ≈ 0.00455`
- 控制错误发现率（**推荐**，功效更高）：**Benjamini–Hochberg FDR**，`q = 0.05`
- 报告必须**同时给出原始 p 与校正后 q**，禁止只报原始 p

**ACF 的额外门槛**：§4.2 的 20 阶 ACF 是 20 次检验。除 BH 校正外，先做 **Ljung–Box 白噪声检验**（滞后 20，α=0.05）；若整体不显著，该期 ACF 结论一律标注"未通过白噪声检验，不构成周期证据"。这直接堵住 v1.0"20 个滞后里总有 1–2 个看起来显著"的漏洞。

### 9.7 统计功效：本项目能测出多大的效果？

在 80% 功效、单侧 α=0.05 下，最小可检测效果 `MDE = (z₀.₉₅ + z₀.₈₀) × SE = 2.487 × SE`：

| 回测窗口 | T | SE | 最小可检测 mean_hits | 最小可检测 lift |
|---|---|---|---|---|
| 全档案 | 277 | 0.0567 | 1.391 | **+11.3%** |
| 近 120 期 | 120 | 0.0861 | 1.464 | +17.1% |
| 近 60 期 | 60 | 0.1218 | 1.553 | +24.2% |

> **这是本项目最重要的一条诚实性结论**：在 277 期真实样本下，系统 lift **小于约 11% 时无法与随机区分**。任何"命中率提升 3%""胜率 55%"的表述在本样本量下都不具统计显著性，报告禁止使用。

有效性档位固定为：

| lift | 判定 | 报告措辞 |
|---|---|---|
| ≥ 1.11 且 `q < 0.05` | 统计显著 | "在本样本下优于随机基线（lift=X，q=Y）" |
| 1.0 ≤ lift < 1.11 | 未达显著 | "略高于随机，但未达本样本可检测门槛（MDE=11.3%）" |
| < 1.0 | 劣于随机 | "未优于随机基线" |

**禁用措辞**：不得把"未达显著"写成"接近有效""有微弱优势""趋势向好""值得关注"。这三种表述是 v1.0 回测章节的默认措辞，v2.0 全部禁用。

### 9.8 退化策略：全部方法失效时怎么办

若 11 个方法全部未通过校正后的显著性检验（这在随机系统中是**预期结果**，不是异常），系统不得伪装有效：

```
if all(q_value[m] >= 0.05 for m in MAIN_METHODS):
    报告 §7.0 一句话结论 → 改为：
      "本样本（277 期）下，系统推荐与随机选取无统计差异。
       以下内容为历史模式的可视化呈现，不构成对未来开奖的预测。"
    §六 终极推荐清单 → 标题改为 "示例性关注清单（无统计显著性）"
    §二 Top5 的信号强度标记 → 全部降级显示 + 统一说明
    退出码 ret_code = 2
```

**默认预期**：实现者应当假设"退化分支会被走到"。诚实性优先于"报告好看"。

## 12. 性能与增量计算

### 12.1 复杂度预算

| 阶段 | 复杂度 | 277 期回测估算 |
|---|---|---|
| 解析两个数据文件 | O(总行数) | < 0.5 s（2063 + 278 行） |
| 拓展集合 | O(20) | 可忽略 |
| 基础统计（每期重算） | O(T × \|expanded\|) | < 1 s |
| 共现矩阵 | O(T × 20²) | < 0.5 s（增量后约 O(20²)/期） |
| **SVD** | O(80³)/期，可缓存 | ~0.02 s/期 → 约 5 s（**唯一热点**） |
| FFT | O(80 log 80) | 可忽略 |
| Louvain / RWR | O(边数 × 迭代) | ~0.05 s/期 |
| **全 277 期回测总计** | — | **目标 < 60 s**（单机、无并行） |

`linalg_svd`（§4.7）是唯一需要处理的性能点。若超预算则按 §12.2 缓存，但缓存键必须含"截至期号"以满足无前视（§9.2）。

#### 12.1.1 实测基线（2026-09-10）

§1.3 已撤回 v1.0 的「278 期回测 < 1 分钟」断言，改为实测。实测结果如下，**与上表的估算差距显著，以本节为准**。

| 场景 | 实测耗时 | 备注 |
|---|---|---|
| 单期完整分析（T=2062 全档案） | 冷启动 ~9 s；热缓存后 ~2 s | `cluster` 的蒙特卡洛零分布按 (window, iters, seed) 全局缓存，只付一次 |
| `daily` 默认回测（最近 60 期） | ~2 分钟 | 用户日常路径 |
| 277 期全档案回测（`--all`） | **9 分 10 秒**（优化前 11 分 45 秒） | ~2 s/期，随历史长度线性增长 |

**实测证伪了"SVD 是唯一热点"**：`linalg_svd` 已不在热点前 12；每期成本由 11 个模块均摊（各约 0.2 s），最大单项是 `markov` 的 HMM 前向-后向（约占 20%），其次 `omission` 的 Weibull MLE（每期 80 次逐号拟合）。

**结论**：§12.2 缓存针对 SVD，而 SVD 不是瓶颈，故加缓存**无法**把回测压到 60 s。剩余瓶颈是「逐号数值递推/拟合」（HMM 的 T 步递推、每号一次 Weibull MLE），**在不改变统计输出的前提下无法数量级加速**；要达 60 s 必须向量化重写统计核心，那会改变模型数值输出、使 §9 的标定与 `tests/golden/` 失效，代价高于收益。

**处置**：按 §1.3，本项以「实测基线 + 已做的**数值等价**优化」结案，不再追 <60 s 的旧目标。已做的等价优化（`tests/test_perf.py` 提供确定性回归护栏）：
1. `entropy` 滑窗计数改前缀和（`_counts` 调用 540+ 次 → 1 次）
2. 共现矩阵累加向量化（逐对 Python 写 numpy 标量 → 花式索引批量累加）
3. `Draw.numbers_set` 预计算（回测中访问千万次）
4. `numerics` 热路径去掉重复 `float()` 转换

若将来确需压缩全档案回测：优先向量化 `markov` 的 HMM 与 `omission` 的 Weibull（按号批量拟合），而非 §12.2 的 SVD 缓存。

### 12.2 增量与缓存

```
# 共现矩阵增量（滑动窗口 W = 100 期）
C[i][j] += 1  for (i,j) in combinations(draw_new)
C[i][j] -= 1  for (i,j) in combinations(draw_old)     # 滑出窗口的那期
```

**等价性是硬要求**：`test_incremental_equivalence`（§10.2）随机抽 20 期比对增量与全量重算，容差 1e-9；不满足则回退全量。

**缓存键**：

```
cache_key = sha256(截至期号 + config_hash + 数据文件内容 hash)
```

- 缓存目录 `data/cache/`（与 §8.5 的只读副本同处）
- **缓存不得跨期复用**：截至期号变化即失效。这是防前视的关键——若像 v1.0 那样按"配置 + 文件"做缓存，就会把未来数据带进回测
- `--no-cache` 强制全量重算，用于排查与 CI

### 12.3 为什么自实现而不引库

| 需求 | 现成库 | 自实现理由 |
|---|---|---|
| GARCH(1,1) | `arch` | 只需固定阶数 MLE，`scipy.optimize` 约 40 行足够；`arch` 依赖重、API 变动频繁 |
| HMM | `hmmlearn` | 隐状态是**遗漏游程**（离散、状态数少），前向-后向约 60 行；引库反而难对齐 §4.5 的状态定义 |
| Louvain | `networkx` + `python-louvain` | 只有 80 节点单层图，模块度贪心约 100 行；且 §4.9 需自定义边权（PMI/Jaccard），库接口更绕 |
| 统计检验 | `scipy.stats` | **这个用库**——超几何、χ²、BH 校正用 `scipy` 保证数值正确 |

原则：**能用 scipy 的数值一律用 scipy；状态定义是本项目特有的算法则自实现**，避免"库的默认行为"与 §4 规格悄悄偏离。
