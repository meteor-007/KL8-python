## 〇、总体结论（先看这一段）

这套系统是围绕「快乐8 (KL8) 80选20 开奖号码预测」的**多子系统矩阵**：11 个分析单元各自实现一套"引擎 + 评分 + 选号 + 回测 + 记忆"闭环，最后由 `数据汇总复盘` 聚合、`kl8-pwa` 调度展示。按架构角色分三类：

| 角色 | 子系统 |
|---|---|
| 预测引擎 | KillSeeker、双层LSTM、顺口溜、gemini选2-预测、定金选2-分析、点位期数-追踪、跟随分析、重点点位分析、data/ |
| 聚合复盘 | 数据汇总复盘 |
| 调度展示 | kl8-pwa |

**跨系统共性结论（最重要）：**

1. **绝大多数"模型/算法"是启发式加权，不是统计可验证模型**。真正的学习模型只有：双层LSTM（DualLSTM）、跟随分析 RF/LR、data/ 的 L2-Logistic + Beta-Binomial + Markov。其余（KillSeeker 四引擎、gemini 量化引擎、定金选2 评分、重点点位 GBDT 融合、顺口溜规则引擎）均为手工调参的线性加权/规则匹配。
2. **多个系统自我评估已接近随机基线（Lift≈1.0）**：定金选2 盲测 Lift 0.93x (p=0.65)、跟随分析 scratch 可行性研究"无显著规律"、gemini 金胆 Lift 1.00x、重点点位 OOF AUC≈0.51 —— 在纯随机开奖上，多数系统**无统计可辨信号**。任何"调参提升"都需警惕过拟合而非真实增益。
3. **共同工程病：死代码密度高、文档与实码严重漂移、双入口/双引擎分叉、未来函数泄漏（look-ahead）集中在回测/回填路径**。
4. **共同健壮性病：正则解析跨系统文本脆弱、期号 `int+1` 跨年断档错误、硬编码绝对路径**。

## 二、双层LSTM（真正的深度学习子系统）

**架构**：DataLoader → FeatureEngine（196 维 11 组特征）→ DualLSTM(128→96) + LayerNorm + 变分/层间 Dropout + AttentionPooling → 3 个 FC 头（80 号码/8 分区/10 尾数）→ Focal+MSE+Ranking 多任务 → 推理 `P_num × zone_adj × tail_adj` 融合 → Top10/金银铜。回测 Walk-Forward。

**P0（确定性问题）**
1. `seed_ensemble.py:62-64` **极差门控是空操作**：`scores=(1-w)*scores+w*mean`（mean 为标量）是仿射变换，不改变排序 → 门控从没生效过。
2. `trainer.py:427-431` backtest 每折缺 `set_seed(base+期数)`（backfill 有，两套 WF 口径不一致），违背 EVAL_CONSTITUTION。
3. **Ranking Loss margin=0.5 与 sigmoid 输出范围（0.49~0.56）严重不匹配**：hinge 恒为 ~0.45 常量，ranking 项白算。这解释了金胆命中率长期低迷。
4. `trainer.py:294-298` 训练丢弃最新 15% 序列（PRD 声称 70/15/15 有 test，实码无 test 且丢弃）。
5. `predictor.load_model` 不读 `ckpt['config']`，config 一改就静默错架构。

**P1**：清理死代码（`compute_ranking_loss_vec` 无调用点、`cross_validate` 死参数、`rolling_window` 死配置、main.py 空分支）；backtest/backfill 复用特征缓存（auto_search 已证明是主瓶颈）；`hypergeom_tail_pvalue`/`set_seed` 三份拷贝收敛；`lstm_model.py` "additive" 注意力分支与 "single" 代码完全相同（假实现）。

**P2（模型层，需 EVAL_CONSTITUTION WF≥30 协议验证）**
- 输出概率压缩在 0.49~0.56：logit 温度锐化 / 改 softmax set 预测（Gumbel-top-k）/ logits 尺度 ranking。
- 早停/选 best 按验证集 Top10 命中率而非复合 loss。
- 每日训练与回测口径统一；特征 A/B 加滚动频率/热冷号；warm-start 增量训练。
