# 项目记忆文档（外置长期记忆）

本文件是项目的“跨会话记忆基线”。

## 1. 记忆声明（必须阅读）

- 模型没有可靠的隐式跨会话长期记忆。
- 项目的长期记忆以本文件和 `docs/AI_CHANGELOG.md` 为准。
- 新会话开始时，必须先读取本文件，再读取改动日志最近 N 条。

## 2. 重启必读区（当前快照）

### 2.1 当前目标

- 目标：把系统稳定为“数据分析系统”并形成可持续的文档治理与协作机制。
- 当前阶段：文档体系首版落地完成，进入“按提交持续维护”阶段。

### 2.2 进行中任务

- 持续按提交更新 `docs/AI_CHANGELOG.md`
- 持续按里程碑更新 `README.md` 与 `docs/AI_TEAM_PLAYBOOK.md`
- 排查并逐步清理历史编码乱码遗留

### 2.3 关键约束

- 启动入口固定：`python .\src\data\start_service.py`
- 前端开发端口固定：`5173`
- 文档语言默认：中文
- 改动记录粒度：每个提交一条

### 2.4 未决决策

- 是否引入自动化脚本（提交后自动追加 changelog 草稿）
- 是否新增文档质量检查（CI 校验 README 导航与 docs 完整性）

### 2.5 主要风险

- 数据源延迟会导致复盘结果异常（待开奖/缺失）
- 文档若未随提交维护，会快速失真

### 2.6 下一步建议

1. 给 `AI_CHANGELOG` 增加“提交后自动补 hash”的半自动流程。
2. 给 `PROJECT_MEMORY` 增加“本周重点目标”滚动区。
3. 在 README 增加“故障排查手册”章节（端口、编码、数据同步）。

## 3. 上下文恢复协议（SOP）

新会话建议按以下顺序执行：

1. 读取 `docs/PROJECT_MEMORY.md`（本文件）
2. 读取 `docs/AI_CHANGELOG.md` 最近 10 条
3. 读取 `README.md` 的“已知问题与后续路线”
4. 再进入代码实现或需求澄清

## 4. 会话更新规范

每次完成一个可交付改动后，至少更新：

- `docs/AI_CHANGELOG.md`：追加本次提交记录
- `docs/PROJECT_MEMORY.md`：更新“进行中任务 / 风险 / 下一步”
