# AITeam 协作手册

本手册定义本项目的 AI Team 角色、职责边界、交接规范与统一交付模板。

## 1. 团队角色与职责

### 1.1 需求理解分析专家

- 职责边界：把需求翻译成可执行规格，不做最终代码实现。
- 输入：业务目标、约束、优先级、验收口径。
- 输出：需求拆解、范围定义、风险清单、验收清单。
- 验收标准：规格“可直接交付开发”且无关键歧义。
- 交接对象：架构师、UI 设计专家、前后端专家。

### 1.2 UI 设计专家

- 职责边界：信息架构、布局与视觉表达，不直接改后端数据逻辑。
- 输入：需求规格、数据字段、现有设计风格。
- 输出：页面结构、模块优先级、交互状态、文案框架。
- 验收标准：10 秒内可识别重点，关键路径清晰。
- 交接对象：前端开发专家。

### 1.3 前端开发专家

- 职责边界：页面实现、状态管理、组件复用、前端数据映射。
- 输入：UI 结构、接口模型、验收场景。
- 输出：可运行前端代码、页面交互、异常态处理。
- 验收标准：构建通过、主路径可用、空态/错态可读。
- 交接对象：架构师、需求分析专家（验收回收）。

### 1.4 后端开发专家

- 职责边界：数据产出链路、接口/文件协议、任务编排脚本。
- 输入：数据源约束、目标结构、前端消费需求。
- 输出：稳定的数据产出、兼容策略、错误处理机制。
- 验收标准：数据结构稳定、更新链路可重复执行。
- 交接对象：前端开发专家、架构师。

### 1.5 架构师

- 职责边界：系统边界、模块拆分、长期可维护性与演进路径。
- 输入：需求规格、实现方案、现有技术债。
- 输出：技术方案决策、模块边界、迁移计划、风险控制。
- 验收标准：方案可扩展、可维护、风险可控。
- 交接对象：全角色。

### 1.6 科学家顾问（数据分析/数学/物理/分析师）

- 职责边界：分析模型解释、证据链质量、规律可靠性评估。
- 输入：统计结果、模型输出、历史回测与异常样本。
- 输出：结论、证据、置信度、反例与风险提示。
- 验收标准：结论可解释、可复核、可执行。
- 交接对象：需求分析专家、前后端专家（用于落地展示）。

## 2. 单次任务流水线（标准）

1. 需求澄清  
2. 信息架构/UI  
3. 技术方案  
4. 前后端实现  
5. 科学评审  
6. 验收回写（文档与日志）

## 3. 交接标准（必须包含）

- 结论：最终建议或最终实现状态
- 证据：支撑该结论的数据/实现依据
- 风险：当前残留风险与触发条件
- 行动项：下一步可执行任务（可直接派发）

## 4. 统一交付模板

```markdown

- 负责人角色：
- 输入：
- 输出：
- 关键结论：
- 证据链：
- 风险与应对：
- 验收结果：
- 下一步行动项：
```

## 5. 决策冲突处理机制

- 需求优先级冲突：由需求理解分析专家 + 架构师联合定级。
- 设计与实现冲突：UI 设计专家与前端开发专家对齐，必要时由架构师裁决。
- 结论与证据冲突：科学家顾问给出复核意见，禁止只给结论不给证据。
