# KillSeeker PRD

## AI 速读卡

- 产品一句话：基于四引擎融合（相似走势+密集区域+形态识别+曲线分析）的 KL8 杀号预测系统，通过低分高置信杀号策略实现 ≥75% 杀号命中率。
- 核心循环：历史数据加载 → 四引擎信号采集 → 加权评分 → 低分杀号/高分保留 → 分层输出 → 复盘验证。
- 目标平台：Windows PowerShell / Python 3.10+ 命令行工具。
- 硬约束：引擎评分越低=越不可能出=高置信杀号；杀号命中率目标≥75%；空间均衡约束（每十年区间最多杀4个，最少覆盖6个区间）；**禁止计算/报告 Hurst**（快乐8本质纯随机，无预测价值）。
- 推荐默认：引擎权重 pattern=69.8%/density=27.8%/curve=1.6%/similarity=0.8%；高置信杀10/中置信杀10/观察区杀5/保留20。
- 发挥空间：引擎权重调优、信号采集算法迭代。
- P0 验收：`python main.py --full` 在含≥60期历史数据的目录下执行，输出高/中/低置信杀号+保留号+复盘报告+回测验证。
- 最容易翻车：引擎权重严重失衡（pattern=69.8%+similarity=0.8%）；杀号空间分布不均导致某区间过度杀号。
- 超预期机会：引擎贡献可视化仪表盘；杀号命中率趋势图。

## 第一章：产品概述

KillSeeker 是一款 KL8 杀号预测系统，让数据分析用户能够基于四引擎融合评分排除不可能开出的号码，从而缩小选号范围，而无需依赖人工经验排除。

### 1.1 差异化对比表

| 功能 | 传统杀号工具 | 通用排除系统 | 本产品 |
|---|---|---|---|
| 引擎融合 | 单一规则排除 | 需自定义 | 四引擎融合（相似走势+密集区域+形态识别+曲线分析） |
| 评分逻辑 | 简单频率排除 | 需自定义 | 引擎评分越低=越不可能出=高置信杀号 |
| 分层输出 | 无或单一列表 | 需自定义 | 三层杀号（高/中/低置信）+ 保留号对比验证 |
| 自适应 | 无 | 需手动配置 | 固定权重 + 空间均衡约束 |
| 空间均衡 | 无 | 无 | 每十年区间最多杀4个，最少覆盖6个区间 |
| 回测验证 | 无 | 需自定义 | N 期回测 + 逐期详细复盘 |
| 复盘对账 | 无 | 需自定义 | 每期杀号 vs 实际开奖对账 + 漏杀标记 |

### 1.2 三类用户画像

**用户 A：选号优化者**
- 核心目标：通过杀号缩小选号范围，提高选号效率
- 对现有工具最大的不满：杀号准确率低，经常杀错
- 让他们愿意切换的那一个功能：四引擎融合杀号 + ≥75% 命中率 + 分层置信度

**用户 B：策略验证者**
- 核心目标：验证杀号策略的长期有效性
- 对现有工具最大的不满：缺乏回测和复盘机制
- 让他们愿意切换的那一个功能：N 期回测 + 逐期详细复盘对账

**用户 C：聚合系统开发者**
- 核心目标：获取杀号信号接入 V18.0 聚合系统作为定胆互补
- 对现有工具最大的不满：输出格式不统一，缺乏置信度标记
- 让他们愿意切换的那一个功能：结构化 JSON 输出 + 三层置信度 + 保留号对比

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| 四引擎融合杀号（核心能力） | 定胆推荐（杀号与定胆是互补功能，不在本系统范围） |
| 三层置信度输出（高/中/低） | 实时杀号（引擎依赖完整历史数据） |
| 四引擎固定权重 + 空间均衡约束 | 跨彩种适配（架构专为 KL8 80选20 设计） |
| N 期回测验证（效果验证） | GUI 界面（定位为 CLI 工具） |
| 逐期复盘对账（漏杀标记） | 自动策略调整（权重固定，不做自动优化） |
| 空间均衡约束（防过度集中） | 深度学习模型（四引擎已足够，无需深度学习） |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| 引擎评分越低=高置信杀号 | pattern=69.8%/density=27.8% | 引擎权重可调 |
| 杀号命中率目标≥75% | 高置信杀10/中置信杀10/观察区杀5 | 杀号数量可调 |
| 每十年区间最多杀4个 | 保留号=20个 | 保留号数量可调 |
| 最少覆盖6个十年区间 | 固定空间均衡约束 | 每区间最多杀4个 |
| Bonferroni α=0.000625 | 后续期数=3 | 后续期数可调 |
| FDR-BH q=0.15 | 窗口候选=(3,5,8,10) | 窗口参数可调 |

#### b) 交互流程

```text
用户执行 python main.py --predict
    |
    v
数据加载 (DataLoader)
    |
    +-- 加载 kl8_history_final.txt
    +-- 按期号降序排列（最新在前）
    +-- 数据预检: 最新期号 + 总期数
    |
    v
引擎1: 相似走势匹配 (SimilarityMatcher)
    |
    +-- 取近10期作为查询序列
    +-- 在历史中搜索相似窗口（3/5/8/10期窗口）
    +-- 计算4维相似度（号码重叠/区域分布/趋势曲线/矩阵形状）
    +-- 找到Top5相似期，统计后续期号码出现频率
    +-- → subsequent_freq: {号码: 频率}
    |
    v
引擎2: 密集区域检测 (DensityDetector)
    |
    +-- 取近60期数据
    +-- HDBSCAN/KMeans 聚类检测密集区域
    +-- KDE 核密度估计
    +-- 识别冷寂区域（低密度区域=杀号候选）
    +-- → density_map: 8×10 矩阵
    |
    v
引擎3: 形态识别 (PatternRecognizer)
    |
    +-- 分析最新一期开奖号码的空间分布形态
    +-- 模板匹配: 均匀散/密集块/对角线/水平带/垂直带
    +-- tanh 平滑处理
    +-- → top3_templates + fill_ratio
    |
    v
引擎4: 曲线分析 (CurveAnalyzer)
    |
    +-- Savitzky-Golay 滤波平滑
    +-- Z-score 异常点检测
    +-- 滚动频率窗口分析
    +-- FFT 主周期提取
    +-- → layer1_data + layer2_data + anomaly_points + dominant_period
    |
    v
杀号预测 (KillPredictor)
    |
    +-- 信号收集 (_collect_signals)
    |       |
    |       +-- similarity: 归一化后续频率
    |       +-- density: 密集区域密度映射
    |       +-- pattern: 模板匹配信号
    |       +-- curve: 遗漏回归+频率+马尔可夫状态+趋势
    |
    +-- 加权评分 (_score_numbers)
    |       |
    |       +-- score = Σ(engine_weight × engine_signal)
    |       +-- 权重: pattern=0.698, density=0.278, curve=0.016, similarity=0.008
    |       +-- ⚠️ 禁止 Hurst：不计算、不报告、不参与自适应
    |
    +-- 空间均衡杀号选择 (_select_kills_with_balance)
    |       |
    |       +-- 按评分升序排列（低分=高置信杀号）
    |       +-- 每十年区间最多杀4个
    |       +-- 最少覆盖6个十年区间
    |
    +-- 分层输出
    |       |
    |       +-- 高置信杀号 (10个, 最低分)
    |       +-- 中置信杀号 (10个, 次低分)
    |       +-- 观察区杀号 (5个, 第三低分)
    |       +-- 保留号 (20个, 最高分)
    |
    v
持久化 + 报告生成
```

1. 引擎权重严重失衡（pattern=69.8% + similarity=0.8%），similarity 和 curve 几乎无贡献（"死代码"）。但因系统命中率达标（81.3%），调整权重可能引入噪声，是否调整待评估。

## 第四章：超越竞品的差异化功能

### 第 4.1 节 四引擎融合杀号

**竞品为何没有这个功能**：传统杀号工具依赖单一规则（如频率排除或遗漏排除），缺乏多维度信号融合。通用排除系统需要用户自行设计特征和模型，门槛高且不考虑彩票特有的空间分布特征。

**本产品如何实现**：四个引擎从不同维度评估号码可能性——相似走势匹配从时序模式角度、密集区域从空间聚类角度、形态识别从分布模板角度、曲线分析从趋势周期角度。加权融合后低分号码被判定为高置信杀号。

**风险与应对**：
- 风险：引擎权重严重失衡（pattern=69.8% 主导）。应对：系统命中率达标（81.3%），权重失衡虽存在但调整可能引入噪声，遵循"没有的话就不用调整"原则维持现状。
- 风险：相似走势和曲线分析几乎无贡献（0.8% + 1.6%）。应对：作为结构性保留，在特定市场状态下可能提供增量信号。

### 第 4.2 节 信号处理原则

**设计决策**：快乐8本质纯随机。禁止计算/报告 Hurst，禁止据此切换“混沌套利/趋势市”模式。杀号仅依据四引擎评分 + 空间均衡约束。

**风险与应对**：
- 风险：纯随机基线下杀号置信度波动。应对：通过回测 Lift / 命中率透明评估，不以伪相位指标粉饰可信度。

### 第 4.3 节 空间均衡杀号选择

**竞品为何没有这个功能**：传统杀号工具按评分排序直接取最低分，可能导致某区间过度杀号（如01-10区间杀8个），而其他区间一个不杀，空间分布极度不均。

**本产品如何实现**：`_select_kills_with_balance` 方法在选号时强制空间均衡——每个十年区间（01-10/11-20/.../71-80）最多杀4个号码，最少覆盖6个区间。确保杀号分布均匀，避免局部过拟合。

| 库名 | 用途 | 为何优于替代方案 | 大致包体积 |
|---|---|---|---|
| numpy | 数组运算 | 科学计算基石 | ~15MB |
| scipy | 统计检验 + FFT | 信号处理标准 | ~40MB |
| scikit-learn | KMeans 聚类 | 密集区域检测 fallback | ~30MB |

## 第十一章：开发者交接说明

### a) 实现顺序建议

1. **先建数据加载器**：实现 `DataLoader` 类，解析 `kl8_history_final.txt`，输出 `KL8Draw` 数据类列表。这是一切的基础。
2. **再建四引擎**：先实现引擎2（密集区域检测）和引擎3（形态识别），它们是权重最大的两个引擎。然后实现引擎1（相似走势）和引擎4（曲线分析）。
3. **接着建杀号预测器**：实现 `KillPredictor`，信号收集 + 加权评分 + 空间均衡杀号选择。禁止引入 Hurst。
4. **最后建复盘和回测**：实现复盘对账和 N 期回测验证。

### b) 最可能导致返工的三个决策

**决策 1：引擎权重配置**
- 安全默认：pattern=0.698/density=0.278/curve=0.016/similarity=0.008（当前实现）
- 需改变方向的信号：回测命中率连续3期 < 70%，说明权重失衡已影响效果
- 风险：调整权重可能引入弱引擎噪声降低命中率

**决策 2：混沌套利策略**
- 安全默认：`apply_chaos_arbitrage` 增强均值回归（当前实现）
- 需改变方向的信号：混沌期杀号命中率 < 60%，说明套利策略失效
- 风险：混沌期信号弱，任何策略都难以显著提升

**决策 3：空间均衡约束参数**
- 安全默认：max_kill_per_decade=4, min_kill_decade_coverage=6（当前实现）
- 需改变方向的信号：约束导致高置信杀号命中率下降 >5%，说明约束过严
- 风险：放松约束可能导致局部过拟合

### c) 哪里要严格，哪里可以灵活

| 章节 | 约束/建议 | 原因 |
|---|---|---|
| 低分=高置信杀号 | 约束 | 核心逻辑不可变 |
| 空间均衡约束 | 约束 | 防局部过拟合 |
| 禁止 Hurst | 约束 | 快乐8本质纯随机，报告会误导 |
| JSONL 持久化格式 | 约束 | 跨会话数据一致性 |
| 引擎权重 | 建议 | 可根据回测调整（当前遵循"不用调整"） |
| 杀号数量配置 | 建议 | 可根据需求调整 |
| 引擎算法实现 | 建议 | 可优化各引擎内部算法 |
| 回测期数 | 建议 | 可根据数据量调整 |

### d) 已知的未知项

1. 引擎权重严重失衡（pattern=69.8%+similarity=0.8%）——是否调整待评估，当前遵循"没有的话就不用调整"原则维持现状。
2. 混沌套利模式的均值回归增强策略在极端混沌期效果有限（置信度67.9%），是否需要额外保护机制待研究。
3. HDBSCAN 可选依赖在部分环境不可用，KMeans fallback 的聚类效果是否等价待验证。
